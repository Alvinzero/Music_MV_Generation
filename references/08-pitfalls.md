# 踩坑详解

每条都是实际踩过的：**症状 → 原因 → 修法**。按流程顺序排列。

---

## 1. 并行出图/出视频会丢素材

**症状**：一次并行调用 3 个 ImageGen，结果只多出 2 个文件，其中一个被另一个覆盖。返回的 `localPath` 还都显示正常。

**原因**：产物文件名是「提示词前缀 + 秒级时间戳」。同一次并行调用时间戳相同，前缀也相同（都以 `Cinematic_film_still__vertical` 开头）→ 同名覆盖。

**修法**：让每个提示词以**不同的短前缀**开头，如 `S1 …`、`S2 …`、`V11 …`。前缀进入文件名，就不会撞。
更保险：出完立刻 `cp` 到自己的 `clips/v01.mp4` 标准名。

---

## 2. `output_dir` 参数被忽略

**症状**：明明传了 `output_dir: "…/images/s6"`，所有产物还是落到 `generated-images/`。

**修法**：不要依赖这个参数。统一在调用后用前缀通配 `ls generated-images/S6_*.png` 取回并改名。

---

## 3. xfade 报 "inputs needs to be a constant frame rate"

**症状**：
```
[Parsed_xfade] The inputs needs to be a constant frame rate; current rate of 1/0 is invalid
Failed to configure output pad on Parsed_xfade
```

**原因**：`trim` 滤镜会把 `frame_rate` 重置为 `0/0`。如果 `fps=24` 写在 `trim` **之前**，trim 之后帧率又变回非法值。

**修法**：滤镜顺序必须是
```
setpts=…, trim=duration=…, setpts=PTS-STARTPTS, fps=24, format=yuv420p, settb=AVTB
```
`fps` / `format` / `settb` 全部放在 `trim` **之后**。`settb=AVTB` 负责统一时间基，缺了它也会在别的环节报错。

---

## 4. ASS 颜色全反了（米色渲成蓝色）

**症状**：想要米色 `#EFE6D6`，渲出来是偏蓝的 `#D6E6EF`。

**原因**：ASS 的颜色格式是 `&HAABBGGRR` —— **BGR 倒序**，不是 RGB。

**修法**：写个小函数统一转换，不要手填。
```python
def bgr_a(rgb, alpha=0x00):      # Style 用，带 alpha
    r, g, b = rgb
    return "&H%02X%02X%02X%02X" % (alpha, b, g, r)

def bgr(rgb):                    # 行内 \1c \3c \4c 用，无 alpha
    r, g, b = rgb
    return "&H%02X%02X%02X&" % (b, g, r)
```

## 5. 纸片被描边压成土黄色

**症状**：想要浅色纸片 + 细纸边，结果整块看起来是深土黄。

**原因**：`BorderStyle=3` 时，`Outline` 既是"留白"也是"纸边"的厚度。`Outline=26` + 深色 `OutlineColour` 时，26px 的深色边环占了纸片面积的 30% 以上，视觉上整块都被拉暗。

**修法**：纸边颜色要**接近纸面**（只深一档），不要用对比色。例：纸面 `#FAF2E2`，纸边用 `#E6DCC8`，不要用 `#C9B79A`。

---

## 6. fontsdir 相对路径静默失效

**症状**：ASS 里写了 `\fn ZCOOL KuaiLe`，渲出来是系统默认字体（或豆腐块），日志没有任何报错。

**原因**：`ass` 滤镜的 `fontsdir` 用相对路径时解析不可靠。

**修法**：**绝对路径 + 转义盘符**
```
ass=subs.ass:fontsdir='D\:/project/out/fonts'
```
验证方式：加 `-loglevel verbose`，看到
```
[Parsed_ass] Loading font file 'D:/…/ZCOOLKuaiLe-Regular.ttf'
[Parsed_ass] Using font provider directwrite (with GDI)
```
才算真的加载了。只有 "Loading font file" 没有后续 provider 行，仍可能回退。

---

## 7. 用 heredoc 拼 ASS 会被转义吃掉

**症状**：生成的 ASS 里 `{\an5\pos(390,900)\frz-3.2}` 变成了 `{n5\pos(...)rz-3.2}`，标签全废。

**原因**：`\a` → BEL、`\f` → 换页、`\r` → 回车、`\b`、`\s`，Python/C 字符串转义把 ASS 标签吃掉了。多层 shell + heredoc 会让反斜杠数量更难控。

**修法**：**生成完整 ASS 时直接用文件写入工具落盘**，不要拼字符串再 `open().write()`。
需要程序化生成时，用 `\\` 双写并在本地小脚本里验证首行输出。

---

## 8. 渲到了旧字幕（竞态）

**症状**：明明改了字幕，成片里还是旧的。

**原因**：上一次渲染还在跑，或时间戳先后颠倒——实测出现过 mp4 写出时间（21:35:22）早于 subs.ass 更新时间（21:35:24）。

**修法**：出片后立刻核对
```bash
ls -la --time-style=+%H:%M:%S "out/成片.mp4" out/subs.ass
```
**mp4 必须晚于 subs.ass**，否则重渲。改字幕和渲染串成一条命令，别并行。

---

## 9. 镜头时长均匀分配 → 中段字幕与画面错位

**症状**：30 秒处画面是昏暗房间，字幕却是"将快乐全部收集"。

**原因**：按"总时长 ÷ 镜头数"平均分配，但歌词前半密集、后半稀疏，两者节奏根本不重合。

**修法**：镜头边界按**歌词时间轴**分配（一句一刀或两刀），再吸附拍点。
单镜控制在 4–6 秒。

---

## 10. "慢半拍"——首字被系统性推后

**症状**：每句的首字位置都晚一点，累积起来整段像慢了半拍。

**原因**：为了"首字踩正拍"，把吸附窗口设成 `[start-0.12, start+0.30]` 并优先取正拍。正拍往往落在 start 之后 0.1–0.3 秒，于是**每一句都被往后推**。

**修法**：窗口改成 `[start-0.20, start+0.10]`（略偏前），且**只有在正拍距 start ≤0.06 秒时**才用正拍，否则取最近网格点。
修复后各句首字偏移可收敛到 ±0.05 秒内。

---

## 10b. 整句都晚——歌词表本身的行起点就晚了

**症状**：用户说"很多地方字幕延迟"。你检查了音轨、帧率、渲染时序，全都没问题。

**原因**：LRC / 歌词视频给的**行起点**本身晚 0.05–0.4s。整句跟着晚，
第一句就晚了，观众的第一感知就是"字幕延迟"。这不是渲染 bug。

**修法**：用 `scripts/fit_lines.py` 逐句实测起音（400–1600Hz 能量陡升），
命中的直接替换起点，未命中的用 −0.08s 兜底。3:49 的歌 40 句里命中 22 句，
中位 −0.057s、最大 −0.387s。

**不要整体平移**：偏移是逐句不同的（−0.36…+0.05），全局平移只会让一半句子更糟。

**不要用"谱通量最大峰"**：会锁到鼓点/镲片，中位只有 +0.026s，看起来"没有偏移"，
实际每句都晚。这个方法在本项目上误导了整整一轮。

---

## 10c. 铺满整句 → 越唱越晚

**症状**：句子开头还对得上，越往后越晚；长句的最后两三个字像在追着唱。

**原因**：逐字时间按 `(end-start)/字数` 均分，而长句的尾部常是间奏。
6.9 秒的句子人其实 4.5 秒就唱完了，最后一个字却等到 6.8 秒才亮。

**修法**：只铺 **70%**（大词句 52%），剩下的时间让整句立着，句末统一淡出。
`fit_lines.py` 会把每句的 `win` 一起算出来。

---

## 11. 长句切出"8 个字 + 2 个字"的畸形尾段

**症状**：10 个字的句子被切成前 8 后 2，尾段只闪两个字，很突兀。

**原因**：按 `CHUNK_MAX` 硬切（`cs[i:i+12]`）。

**修法**：**均分**
```python
k = -(-n // CHUNK_MAX)
base_len, extra = divmod(n, k)
# 13字→[7,6]，15字→[8,7]，16字→[8,8]
```

---

## 12. 远景/剪影里有角色 → 模型自由发挥

**症状**：写着"两个极小的人影"，出来是**两个人类女孩**（一个蓝头发一个黄头发），鲸鱼不见了。

**原因**：远景下角色只剩剪影，纯文字提示词保不住身份，模型会按"人物"的常规想象去画。

**修法**：
- 需要角色时用**图生图** + `image1` 传已有角色帧，提示词写
  `Keep the SAME characters with IDENTICAL designs … Now place them in a NEW scene`
- 远景/过渡镜头**干脆不要角色**，用空镜（纸屑飘落、城市灯海），既安全又有呼吸感

---

## 13. 单镜太长靠慢放硬撑 → 高潮段发闷

**症状**：30.3–44.9 一个镜头 14.5 秒，观众觉得"这里是不是少了个镜头"。

**原因**：素材不够，用 2.27x `minterpolate` 把 6 秒拉长到 14.5 秒，画面几乎静止。

**修法**：**先补拍，再考虑慢放**。补 2 镜后这段切成 3 刀（各 4.3–5.1 秒），且这三镜恢复常速播放。
慢放上限 2.5x，超过就必须补拍。

---

## 14. 背影镜头也会换人

**症状**：想要女孩背影，出来戴了宽檐草帽，完全不是同一个人。

**原因**：背影不露脸，但**轮廓**更容易被改——帽子、长发、双马尾，模型加一个就换了人。

**修法**：背影类提示词要把"发型 / 裙子 / 腿"逐项写死，并**显式否定**改变轮廓的元素：
`NO hat, no other characters, short side ponytail that rests on her shoulder`。

---

## 15. 用 scene 检测验证切点 → 结论错误

**症状**：用 `select='gt(scene,0.12)',showinfo` 检测切点，得到的时间和实际切点对不上（有的漏检，有的出现在叠化中途）。

**原因**：渐变叠化不是硬切，scene 分数在叠化过程中是渐变的，峰值位置不可靠。

**修法**：直接核对 filter 脚本里的数学关系——`offset + fade/2` 应等于拍点。用脚本打印每个切点到最近拍点的误差即可。

---

## 16. 素材时长不是整 6 秒

**症状**：按 6.00 秒算时间线，越往后偏得越多。

**原因**：视频模型生成"6 秒"实际是 **6.04 秒**（24fps × 145 帧）。

**修法**：先 `ffmpeg -i clip.mp4` 读实际时长，把 `--clip-len 6.04` 传进时间线脚本。
总时长按音轨实测（如 56.026s），不要取整。

---

## 17. 全片套同一个字幕行位 → 压人脸

**症状**：字幕统一放底部，遇到"人物躺在画面底部看星空"的镜头，字幕正好横在脸上；
改成顶部，仰拍钟楼的镜头又被字幕横穿中轴。

**原因**：`place` 只有顶/中/底三档，本质是把字幕当覆盖层，而不是画面元素。
每个镜头主体位置都不同，一个值不可能全对。

**修法**：**逐句给 `x`/`y`/`fs`**。流程是：出完 `base.mp4` → 按每句中点抽帧拼联系表
→ 在帧上判空档 → 写坐标。装不下就降字号（84→76→72→68→64→56→52），
横穿构图重心时拆成左右两段。完整方法见 `references/05a-subtitle-layout.md`。

**验收**：抽 6–8 帧单帧烧字幕回看，确认人脸、手、乐器、建筑中轴都没被压。

---

## 18. `-ss` 放在 `-i` 之前，字幕滤镜什么都不画

**症状**：抽帧预览字幕，导出的图干干净净一个字都没有，但 `subs.ass` 内容是对的。

**原因**：输入侧 `-ss` 会 seek 后把输出时间戳重置为从 0 开始，
`ass` 滤镜按时间戳取事件，于是认为当前是片头 0 秒，自然没有该句。

**修法**：加 `-copyts` 保留原始时间戳。

```bash
ffmpeg -y -copyts -ss 71.5 -i out/base.mp4 \
  -vf "ass=out/subs.ass:fontsdir='D\:/abs/path/assets/fonts'" -frames:v 1 chk.png
```

或者把 `-ss` 放到 `-i` 之后（输出侧 seek，慢但准确）。

## 工程层补充（本 skill 实测）

### 时间轴

19. **秒和帧混用 → 字幕整体慢半拍**。`0.35s@30fps=10.5 帧`，四舍五入方向不同就漂移。
    只存帧，只在一处换算。
20. **叠化记错归属**。叠化属于「后一个镜头」，推进游标时减的是**下一镜**的叠化帧，
    不是自己的。写成自己的会每镜多走 fade 帧。
21. **慢放系数写成倒数**。要"屏上 N 帧、素材只有 M 帧"，则 `speed = M/N`（<1 才是慢放），
    写成 `N/M` 就变成快放，且总长对不上。
22. **素材比槽位短时直接裁掉**。6.04s 的素材要塞进 6.4s 的槽位，必须慢放 0.94x，
    硬裁会让后续所有镜头的 start 全部错位（错误会以"每一镜都不对齐"的形式刷屏）。

### 渲染

23. **输入超过 20 个时 ffmpeg 报 `get_buffer() failed`**。给每个 `-i` 加 `-threads 1`，
    再加 `-filter_complex_threads 2`。61 个输入实测可过。
24. **`delogo` 的 x 不能为 0**，会报 "Logo area is outside of the frame"，用 `x=3:y=7`。
25. **`-filter_complex_script` 里 ass 的路径要绝对 + 转义盘符**：`fontsdir='C\:/abs/fonts'`。

### 音频

26. **`volumedetect` 的 `mean_volume` 不是 LUFS**。它给的是 RMS，两者能差 2 LU。
    要 LUFS 用 `ebur128` 或 `loudnorm` 的 `print_format=json`。
27. **单遍 loudnorm 打不到目标**。设 `I=-14`，实测出 -12，峰值还顶到 -0.6。
    必须两遍：先 `print_format=json` 测 `measured_*`，再带上这些参数渲一遍（`linear=true`）。
28. **成片没做响度检查就交付**，"听着有点吵"这种反馈会反复出现。`quality_check.py` 一次就能定位。

### 脚本工程

29. **`scripts/inspect.py` 会覆盖标准库 `inspect`**，导致 numpy 直接 import 失败。
    脚本目录会进 `sys.path`，命名必须避开 `inspect / types / json / code / token` 等。
    本 skill 用 `mediainfo.py`。
30. **写文件用工具、不要用 heredoc 拼转义**。`\a \f \r \{` 在 shell 里会被吃掉一层。

### Remotion 后端（实测）

31. **首次渲染会卡在 Chrome 下载**。要 `storage.googleapis.com`，国内 ECONNRESET。
    用 `scripts/fetch_chrome.py` 从 npmmirror 取，或 `--browser` 指本机 Chrome。
    **Edge 不行**：能启动但立刻 `Closed with 0 signal: null`。
32. **Remotion 默认输出 `yuvj420p`（全范围）**，ffmpeg 是 `yuv420p`。混用两个后端会偏色，
    渲染后必须归一化（`render_remotion.py` 已默认做）。
33. **Windows 上 Python 的 `subprocess` 找不到 `npx`**——它是 `npx.cmd`。
    必须 `shutil.which("npx.cmd")` 取全路径，不能直接写 `["npx", ...]`。
34. **`<Transition>` 会让总长变短**。TransitionSeries 里两镜在转场期间同时播放，
    总长 = Σ镜头 − Σ转场。所以每个 Sequence 的 `durationInFrames` 要按"屏上帧数"给，
    而不是"扣掉转场后的净长"，否则尾段会越算越短。

## 19. 片头用 ASS 标题卡压画面 → 挡住场景、推镜时字不跟

**症状**：第一眼看到的是一块米色纸牌横在画面中间；镜头推近时牌子纹丝不动；
用户反馈"标题太丑了而且遮挡了大部分的内容"。

**原因**：把片头当成"一条字幕"来做。字幕层是叠在画面上的，它不参与透视、不参与光。

**修法**：歌名必须**长在画面里**——ImageGen 出无字载体场景 → `make_title.py` 字库排字 →
VideoGen/zoompan 让它动。完整做法见 `references/06-title-card.md`。

---

## 20. VideoGen 写 `slow push-in` 会推过头，把标题裁掉

**症状**：6 秒片段，前 3 秒正常，5.5 秒时字已经被裁出画面。

**原因**：模型把 "push-in" 理解成"明显推进"，6 秒能推 1.5 倍。

**修法**：改**锁机位**提示词（`Locked-off tripod shot … NO zoom, NO push-in, NO dolly`），
negative 挂 `zoom in, push in, cropped banner`。并且**首帧和末帧都要抽出来核对**，
只看第一帧会被骗。反向也成立：上一版写锁机位反而被拉远，标题从 40% 缩到 25%。

---

## 21. VideoGen 的水印在左上角，和 ImageGen 不是一回事

**症状**：按右下角裁完，左上角仍有「AI生成」。

**原因**：两个工具的水印位置不同。

**修法**：VideoGen → `crop=1700:956:110:0`（左右对称裁掉左侧 110px）再 `scale=1920:1080`；
ImageGen → 裁底部（3:4 图裁到 y=1365）。

---

## 22. 片头与下一镜之间做"对黑" → QC 判非预期黑帧

**症状**：`quality_check.py` 报「非预期黑帧 1 处: [[5.88, 6.04]]」，整片不通过。

**原因**：为了缓冲亮度差（片头 mean 39 → 城市远景 mean 12）插了 3 帧 fade to black。

**修法**：**硬切**。亮 → 暗本身就是一次"揭示"，比过渡更有力。
非要过渡就用 xfade 叠化，但叠化会缩短总长，必须在时间轴上先扣掉帧数。

---

## 23. `BorderStyle=3` 的色块底 + Shadow 会画出一圈深色框

**症状**：片头牌子上莫名多了一层深色描边，像双线框。
**原因**：`BorderStyle=3` 时 libass 用 `\4c` 画一层带偏移的影子矩形，`Shadow>0` 就露出来了。
**修法**：把 `\4c` 设成和牌面同色让它隐形，或 `\shad0`。

---

## 24. 分层字幕只对齐一层，否则两层会互相错开

**症状**：一句里有的字早 1.7s、有的字晚 1.2s；辉光层和实字层错位，看起来像重影。

**原因**：无卡字幕是"辉光层 + 实字层"两个 Dialogue，同一句的字被混进同一个分组里，
DP 把两层分到不同的峰上。

**修法**：只对齐实字层（layer 2），再把同样的位移按"同文本 + 同原始起点"套到其它层。
实测修之前最大位移 1.22s，修之后 0.28s。

**顺带**：这也说明"通过 0.3s 门槛"不等于没问题——门槛量的是"字是否落在可信起音上"，
两层错位时每个字都还落在起音上，只是落在了不同的起音。所以**分层字幕必须肉眼抽两帧**。
