# 字幕布局：逐镜适配

字幕不是"顶 / 中 / 底"三选一。**同一个片子里，每一句的字幕位置和字号都应该不一样**，
因为它们落在不同的画面上——有的画面主体在中间，有的在底部，有的整幅都是人。

固定一行字幕反复出现在同一个高度，本质上是把字幕当成"覆盖层"；
正确的做法是把它当成**画面里的一个元素**，去找那块本来就空着的地方。

---

## 一、先摆画面，再摆字幕

字幕只有一个硬约束：**不许压主体**。

主体包括：

- 人脸（最重要，压脸一帧都不能忍）
- 正在做动作的手 / 乐器 / 道具
- 建筑中轴（钟楼、门框、雕塑这类构图重心）
- 人群密度最高的那块区域

主体之外的一切——天空、地面、空墙、桌面、远景虚焦——都是可用的。

> 常见错误：整片用"底部居中"，遇到"人物躺在画面底部"的镜头就会压脸；
> 改成"顶部居中"，遇到"仰拍钟楼"的镜头又会压塔尖。
> 所以必须**逐镜看**，不能全局定一个值。

---

## 二、三步法

### 第 1 步：按每句中点抽帧

字幕时长通常和一句歌词等长，取中点那一帧最能代表整句的画面。

```bash
python - <<'EOF'
import json, subprocess, imageio_ffmpeg
FF = imageio_ffmpeg.get_ffmpeg_exe()
for n, it in enumerate(json.load(open("out/lines.json")), 1):
    t = (it["start"] + it["end"]) / 2
    subprocess.run([FF, "-y", "-v", "error", "-copyts", "-ss", str(t),
                    "-i", "out/base.mp4", "-frames:v", "1", f"qa/lines/L{n:02d}.png"])
EOF
```

再拼联系表，一次看 12 帧：

```bash
ffmpeg -y -start_number 1 -i qa/lines/L%02d.png -frames:v 1 \
  -vf "scale=480:270,tile=3x4:padding=4:margin=4" qa/lines/S1.jpg
```

> `-copyts` 必须加。不加的话 `-ss` 之后时间戳从 0 重新计，字幕滤镜会以为这是片头，
> 什么都不画，你会误判成"字幕没生成"。

### 第 2 步：在帧上判空档

对每一帧问三个问题：

1. 主体在哪？（框出人脸和主要动作的范围）
2. 剩余空间里，哪一块最完整、最不打断构图？
3. 这一块的**可用宽度**够放几个字？

常用落点，按优先级：

| 落点 | 适用 | 注意 |
|---|---|---|
| 主体正下方的地面 / 桌面 | 人站着、站着走路、坐着 | 别压到脚和投影 |
| 主体上方的天空 / 空墙 | 仰拍、躺姿、低机位 | 别压到头顶和建筑尖顶 |
| 画面一侧的空白 | 主体偏左/偏右、特写 | 优先选留白更宽的一侧 |
| 两个主体之间的空隙 | 双人对峙、对坐 | 空隙窄时要缩字号 |
| 建筑中轴的两侧 | 对称构图（钟楼、大门） | 宁可拆成两段，也不要横穿中轴 |

### 第 3 步：写进 lines.json

```json
{"start":68.0,"end":73.0,"text":"躺在你学校的操场看星空","x":1250,"y":565,"fs":56}
```

- `x` / `y`：**整行的中心点**（不是左上角）
- `fs`：该句字号
- 三个字段都可省，省了退回 `place`(T/M/B) 与默认 84

---

## 三、字号：装不下就降一档

纸片宽度 = `fs + 2×纸边`，纸边 ≈ `fs × 0.26`。所以：

| fs | 单字占宽 | 字缝 | 一句 10 字约需 |
|---|---|---|---|
| 84 | 128 | 12 | 1388 |
| 76 | 116 | 10 | 1250 |
| 72 | 110 | 10 | 1190 |
| 68 | 104 | 9 | 1121 |
| 64 | 98 | 9 | 1061 |
| 56 | 86 | 7 | 923 |
| 52 | 80 | 7 | 863 |

判定：`可用宽度 ≥ 字数 × 单字占宽 + (字数−1) × 字缝`，否则降一档再算。

经验值：

- 满幅底部行：84（手机上也读得清）
- 主体下方有 800–1000px：76
- 挤在两个人之间 / 一侧窄空白：64–68
- 只有 900px 左右的天空缝：56
- 画面已经被主体占满（躺姿、大特写）：52，贴着画面最下沿

> 宁可小一点，也不要糊在人脸上。观众能读到字的前提是**先看清画面**。

---

## 四、什么时候拆成两段

两种情况：

1. **超过 12 字**——脚本自动均分，不用管。
2. **一句话横穿构图重心**——比如正面仰拍的钟楼、对称的大门、正中的单人特写。
   这时可以把一行拆成两组，分别塞进左侧和右侧的空白。

拆段要在 `lines.json` 里写成两条记录（时间首尾相接），不要指望一条记录自动左右分栏。
两条记录的 `x` 分别给左右两侧的中心，`y` 可以不同（跟随各自那侧的空档高度）。

---

## 五、时间轴与位置的耦合

一句歌词可能横跨两个镜头。这时位置要**照顾时长更长的那一镜**，
或者选一个两镜都成立的位置（通常是画面最下沿的窄条）。

判断方法：看这句的 `start`/`end` 各落在哪个 `bounds` 区间里，取覆盖时间更长的那个镜头的构图。

## 六、验收

```bash
# 只烧字幕、不重渲全片，快速回看
ffmpeg -y -copyts -ss 71.5 -i out/base.mp4 \
  -vf "ass=out/subs.ass:fontsdir='D\:/abs/path/assets/fonts'" \
  -frames:v 1 qa/chk/c1.png
```

逐条检查：

- [ ] 人脸、手、乐器、道具一个都没被压
- [ ] 建筑中轴没有被横穿
- [ ] 整行左右不出画（`x ± 半宽` 在 30–1890 内）
- [ ] 整行上下不出画（`y ± 半个纸片高` 在 8–1072 内）
- [ ] 相邻两句不在同一个高度机械重复——位置要跟着画面走
- [ ] 缩小过字号的句子，仍然读得清（1080p 下不小于 52）

---

## 七、反面清单

- 全片一个 `place` 到底 → 一定有若干镜头压主体
- 为了"整齐"把所有句子对齐同一基线 → 画面被切成一刀两半
- 遇到挤就换行成两行 → 纸片字幕两行会互相压住，宁可信箱式缩字号
- 只在大屏上看效果 → 手机竖屏播放时底部会和进度条打架，靠下的行留 60px 余量
