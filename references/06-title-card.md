# 片头：歌名怎么"长"进画面

片头是全片唯一一处**观众还没进入情绪就先看到字**的地方。它做错，比全片任何一镜都显眼。

这份文档只讲片头：歌名、歌手、载体、怎么动起来、怎么验收。
字幕的正片样式归 `subtitle-styles.md`，这里不重复。

---

## 一、一条铁律：片头信息不是字幕层

**不能**用 ASS 字幕把一个"写着歌名的卡片"叠在画面上。哪怕它很好看。

理由不是洁癖，是三条一眼就假的症状：

| 后期叠上去 | 长在画面里 |
|---|---|
| 镜头推近，字纹丝不动 | 字跟着画面一起放大 |
| 纸在飘，字钉死在屏幕上 | 字随纸一起摆 |
| 纸有透视和褶皱，字是正面平的 | 字贴着那个面走 |

**反面教材（本 skill 真实踩过）**：给一首夜戏 MV 做片头，用 ASS 画了一块
790×286 的米色纸牌压在画面正中，位置 y=470。结果：

- 纸牌盖住了整个纸雕场景的中央，观众第一眼看到的是一块白板
- 推镜时牌子是死的，和画面分离
- 用户的原话：「这个标题太丑了而且遮挡了大部分的内容」

同一套做法在暖米色日景里能勉强成立（纸牌和画面同色系），**在暗调画面里必定崩**。
所以不要有"这次应该也行"的侥幸。

## 二、先选载体：字写在什么上面

载体必须**有出处**——它得是这个世界里本来就会存在的纸：

| 载体 | 适合的歌 | 为什么成立 |
|---|---|---|
| 街口竖挂的纸幡 / 招牌 | 城市、孤独、被忽视 | 一个没人抬头看的名牌 |
| 作业本 / 试卷 | 校园、暗恋 | 名字写在封面上 |
| 车票 / 票根 | 离别、远行 | 目的地和日期都写在纸上 |
| 信封 / 信纸 | 思念、旧事 | 收信人就是歌名 |
| 便签 / 备忘录 | 日常、自述 | 随手写下的一句话 |

**不要**用一块干净的空白纸板。它没有出处，谁都能用，等于没有设计。

### 署名放哪里：歌名居中，但署名可以拆出去

"文字块居中"说的是**歌名**，不是"歌名+歌手"拼成的那一大块。两者混为一谈，换个画面就翻车。

实测案例：片头正中立着一座钟楼，表盘落在 (975, 420–500)。按"整块居中"把歌名和署名一起下移，
40px 的"周杰伦"正好压在表盘刻度上——深色小字叠深色指针，手机上读不出来。

正确的解法不是把标题挪走（那就不居中了），而是**把署名从标题块里拆出去**：

| 元素 | 位置 | 理由 |
|---|---|---|
| 歌名 | 中心 y≈556（画布中线 540，低 16px） | 视觉居中；略低于中线反而更稳 |
| 署名 | y=292，歌名上方 260px 的天空带 | 做眉标，避开实体，不破坏居中 |
| 分隔线 | 去掉 | 压在云层里等于没有，还添乱 |

**判据**：画布中心 ±120px 内若出现高对比实体（钟楼、人脸、招牌、强边缘），
不要再把署名塞在标题旁边，按这个顺序选位置：

1. **标题上方的干净带**（首选，做眉标）
2. **画面下沿做小字幕 36–40px**（次选，最稳，但要确认不压主体）
3. 标题左右两侧的空带（最后，破坏对称，慎用）

**实测参数**（1920×1080，5 字标题）：

```
字号 196 / 字距 22   →  宽 1068px = 55.6%（贴着上限；超过 58% 就显得满）
标题实际像素 y = 468..649（中心 556）
署名 40 / 字距 14，y = 292
柔投影 blur 9 / alpha 130，偏移 +8px
推镜 1.00 → 1.07，锚点锁画面中心
```

**推镜的副作用要知道**：`zoompan` 以锚点为中心外扩，`out_y = 540 + (y-540)*z`。
放在中线附近的元素几乎不动（556 → 555），离中线越远位移越大。
所以"居中"不只是好看，它还能让标题在推镜过程里保持稳定。

```python
# 按墨色相似度量标题实际位置，比灰阶阈值可靠
im = np.asarray(Image.open(f).convert("RGB"), dtype=int)
band = im[:, 420:1500]                            # 只取横向中段，避开两侧深色纸影
d = np.abs(band - np.array([48, 34, 24])).sum(2)  # 标题墨色
rows = np.where((d < 45).sum(1) > 60)[0]          # 每行超过 60 个墨色像素才算字
print("标题 y=%d..%d 中心 %.0f" % (rows.min(), rows.max(), (rows.min() + rows.max()) / 2))
```

⚠️ 别用"灰阶 < 100"当判据：纸雕的屋檐阴影、门洞、深色纸边都会中招，
实测量出"占宽 99.5%"这种完全失真的数字。

**改完片头必须同步重制无字幕母版**，否则下次改字幕时烧的还是旧标题：

```bash
# 新片头（125 帧）+ 母版去掉前 125 帧，一次编码拼回
ffmpeg -y -i out/title_v2.mp4 -i out/base.mp4 -filter_complex \
  "[1:v]trim=start_frame=125,setpts=PTS-STARTPTS[b];[0:v][b]concat=n=2:v=1:a=0[v]" \
  -map "[v]" -c:v libx264 -crf 18 -preset medium -pix_fmt yuv420p -an \
  -t 291.75 out/base_titled.mp4
```

## 三、三段式：出无字场景 → 排字 → 让它动

### ① ImageGen 出一张**完全没有字**的载体场景

```
macro photograph of a handcrafted paper-cut diorama at night, symmetric frontal
composition, MEDIUM CLOSE-UP: one blank rectangular signboard of cream torn paper
hanging from a slim paper bracket, centred in frame and filling about 60 percent
of the frame width, its face parallel to the camera and perfectly flat, glowing
warm amber from a hidden light behind it, <环境>,
absolutely no text, no letters, no characters, no writing, no signage, no logo
```

三个必写：`centred in frame`、`parallel to the camera and perfectly flat`（要平，才能排字）、
`absolutely no text`（正向写完反向再写一遍）。

> **载体必须生成在画面正中。** 偏左或偏右的载体，后面只有两个选择：把字跟着排偏（违反"文字站中间"），
> 或者裁一刀把载体挪回中间（损失构图）。第一步就让它在中间，后面全省事——
> 跑 `--vertical` 时脚本会打印"字块中心 vs 画面中线"，偏了就是载体没居中，回去重出图。

### ② 用字库把字排进去（`scripts/make_title.py`）

字库排 = 零错字。比让模型画中文靠谱一个数量级，尤其是署名这种小字。

> **为什么封面可以直出、片头却要字库排？** 两者的容错不一样：
> 封面是**一张静态海报**，只要字对、位置对就完事，模型直出还能让字跟着褶皱走；
> 片头是**要动起来的 6 秒**，竖排 6 字 + 小署名 + 被推轨带着走，一旦模型丢了字或加了料，
> 整段视频得重生成。片头走"字库排进首帧、模型只负责运动"，字就永远不会错。

**横排（横幅、信纸、车票）**

```bash
python scripts/make_title.py --src images/plate.png --title "手写的从前" --singer "周杰伦" \
    --cy-title 505 --singer-y 292 --singer-size 40 --no-line --still out/title_still.png
```

`--cy-title` 是歌名文字块的**中心 y**，`--singer-y` 是署名的 y。
这两个数没有通用值——上一支片量出来是 505 / 292（歌名居中偏下、署名作眉标压在塔尖上方），
换一部片必须重新定：先跑 `--no-video` 出静帧，看一眼再调。

**竖排（纸幡、竖招牌）**——这次踩的坑就在这条路上：

```bash
python scripts/make_title.py --src images/plate.png --title "无人知晓的我" --singer "A-LIN" \
    --vertical --area 760,66,1160,622 --still out/title_still.png --no-video
```

`--area x0,y0,x1,y1` 是**载体在源图里的范围**（不是画面范围）。脚本会：

1. 先按"n 个字 + 字距 + 署名"算出能放下的最大字号
2. **强制上下各留 ≥6.5% 载体高**——放不下就自动降字号，一直到装得下
3. 打印实测值：占载体高、首字距顶、末字/署名距底、字块中心与载体中线差

```
竖排 6 字 字号 70  占载体高 86.3%
首字距载体顶 40px（7.2%）  末字/署名距底 36px（6.5%）
字块中心 x=960（载体中线 960，差 -0）
```

> **这一条是这次返工的直接原因**：手写版按载体高度算满（93%），
> 首字顶到纸边 3.6%，用户一眼看到"字跑出去了"。
> 现在留白由脚本强制，不看也会守住；如果字号被降到 40 以下，说明载体本身太小，
> 该回去把纸幡生成得更高，而不是继续挤。

字怎么"压进纸里"（脚本已内置）：

- 用**底图亮度调制墨的不透明度** —— 纸纹处墨淡一点，看起来是吸进去的
- 向下 2px 打一层 35% 的压印暗层
- 0.5–0.6px 高斯，去掉矢量锐边
- 暖墨 `#2B2118`，**不要纯黑**（纯黑在米纸上像贴纸）

### ③ 让这一帧动起来

**推荐：VideoGen 图生视频**（纸边会颤、灰会飘、窗光会闪，字在第一帧里烫死，不会错）。

```
image      : out/title_still.png
seconds    : 6
resolution : 1080P
audio      : false
prompt     : Locked-off tripod shot, completely static camera. NO zoom, NO push-in,
             NO dolly …（见第四节坑 1）
negative   : zoom in, push in, dolly in, camera movement, warped text,
             changed characters, extra text, cropped banner
```

**备选：zoompan 推镜**（最稳，但只有推，没有环境感）：
`zoompan 1.00 → 1.07 / 125 帧`，锚点放在载体中心。

> **什么时候放弃 VideoGen**：抽首末帧发现字被推歪、笔画糊掉、或者载体变形——
> 直接退回 zoompan。宁可少一点"环境感"，也不能让歌名在动的时候发抖。

> **片头留 5–6 秒。** 六个竖排字 + 署名，少于 4 秒读不完；超过 7 秒观众会开始等。
> 本次是 5.92 秒（142 帧），前 1.4 秒还在淡入，实际可读约 4.5 秒——刚好。

### ④ 接回正片（这一步最容易漏）

片头不是独立文件，它要占掉时间轴的第一段，**总帧数必须不变**：

1. 定片头帧数 `N`（24fps 下 6 秒 = 144 帧，5.9s = 142 帧）
2. 把生成片段裁水印、补亮度、转成 `clips/s01.mp4`，`-frames:v N`
3. **从原来的前奏段里切出这 N 帧**（原 3 镜 → 片头 + 2 镜），不要整体加长：
   全片总帧不变，字幕和后面的镜头就都不用动；一旦整体加长，所有时间点全部错位
4. 重新 concat → 重渲 → 跑 `quality_check.py`
5. **成片 mtime 必须晚于字幕文件**，否则你渲的是旧的

> 改片头等于改整条时间轴的第一段：字幕不用动（歌词从 13.0s 才起），
> 但 `shots.json` / `timeline.json` 的前三镜时长要跟着改，否则核对时会以为总长对不上。

## 四、VideoGen 这条路的四个坑（都是实测）

### 坑 1：写 "slow push-in" 它会推过头

第一次提示词写 `Slow cinematic push-in`，6 秒里模型推了约 1.5 倍，
到 5.8 秒时**标题已经被裁出画面**。

改写成锁机位：

```
Locked-off tripod shot, completely static camera. NO zoom, NO push-in, NO dolly,
NO camera movement whatsoever for the entire shot: the framing must stay exactly
identical to the first frame, with the whole banner fully visible and comfortable
dark margins above the bracket and below the banner.
```

negative 挂 `zoom in, push in, dolly in, camera movement, cropped banner, banner leaving frame`。
实测锁机位版本 6 秒全程不出画。

> 但要注意反向的经验：上一版做动画 MV 时，写 `locked-off` 反而被模型**拉远**，
> 标题从 40% 缩到 25%。结论不是"哪个提示词更对"，而是——
> **两版都要抽首尾帧核对**，不许只看第一帧。

### 坑 2：VideoGen 的水印在**左上角**，和 ImageGen 不是一回事

| 工具 | 水印位置 | 规避方式 |
|---|---|---|
| ImageGen | 右下角 | **16:9 底图**裁 `crop=1755:987:0:0`；**3:4 底图**裁 `crop=0,0,1024,1365` |
| VideoGen | **左上角**（约 x<110, y<70） | 对称裁：`crop=1700:956:110:0` 再 scale 回 1920×1080 |

只裁左边会破坏构图，要左右对称裁；裁掉的 110px 里正好含水印。
**两个工具的水印不在同一个角**，按老习惯裁另一边会留下半截字。

### 坑 3：生成片段自己会越来越亮

实测一段 6 秒的夜景：`mean luma 60.7 → 74.4`（雾升起来了）。
接到后面的暗镜头上会像曝光跳了一档。

用逐帧亮度补偿压回去：

```
eq=brightness='-0.056*min(t/5.9,1)':eval=frame
```

系数 = (末帧均值 − 首帧均值) / 255，符号取负。补偿前后实测：

| 时间 | 补偿前 | 补偿后 |
|---|---|---|
| 0s | 60.7 | 67.7（裁切后整体抬高，但这 1.4 秒还在淡入，看不见） |
| 3.0s | 65.0 | 60.3 |
| 5.8s | 74.4 | 60.7 |

可读区间（3s 之后）从 +9.4 的漂移收到 **±0.4**，接到后面的暗镜头不再像曝光跳档。

### 坑 4：别做"对黑"过渡，QC 会判非预期黑帧

片头（亮）接城市远景（暗），中间插了 3 帧对黑，`quality_check.py` 直接判
**"非预期黑帧 1 处"** 不通过。

正确做法：**硬切**。亮 → 暗本身就是一次"揭示"，比过渡更有力。
真要过渡就做叠化（xfade），但叠化会改变总帧数，得在时间轴上先扣掉。

## 五、如果片头非要走 ASS（只能用在这两种情况）

1. 片子本来就是**白底/亮底**的图形动画，没有"画面里的纸"可以承载
2. 用户明确要求"标题卡"这种版式

此时必须注意：`BorderStyle=3`（色块底）配 `Shadow>0` 时，libass 会在字块**外面**
再画一层带偏移的暗色矩形，看起来像多了一个框。

修法：把 `Shadow` 颜色的 `\4c` 设成**和纸牌同色**，让它隐形；或者干脆 `\shad0`。
（本 skill 第一次就栽在这——片头牌子上莫名多了一圈深色描边。）

## 六、交付前自检（7 条，全部要过）

- [ ] **首字没有贴到载体边缘**：上方留白 ≥ **载体高的 6.5%**，末字/署名到载体底 ≥ 6.5%。
      走 `make_title.py --vertical` 的由脚本强制守住；走 ImageGen 直出的**必须用眼睛量**
- [ ] **标题占载体高 60–87%**。这个区间是"上下各留 6.5%"反推出来的：
      低于 60% 说明字太小、整块发虚；超过 87% 说明载体太紧，回去把载体做高，
      不要靠继续压字号
- [ ] **文字在画面中间**：字块中心 = 载体中线（±8px）= 画面水平中线（±8% 画宽）。
      偏到一侧就不是这个版式了，读起来像贴角标
- [ ] **抽首帧和末帧**，确认全程没出画、没被裁、字没变形
- [ ] **水印已裁掉**（ImageGen 在右下 / VideoGen 在左上，位置不同，裁法也不同）
- [ ] **总帧数对得上**：片头占 `N` 帧，后续镜头起点 = `N/24`s，全片总帧不变
- [ ] **缩到 375px 宽**还能读；片头信息在手机上一眼认不出来，等于没做

## 七、一句话总结

> 片头不是"把字排上去"，是**给这首歌找一张纸，把名字写在上面，再让这张纸被镜头看见**。
> 字库负责不出错，模型负责让它动起来，人负责核对它有没有出界。
