# 片头：歌名怎么"长"进画面

片头是全片唯一一处**观众还没进入情绪就先看到字**的地方。它做错，比全片任何一镜都显眼。

这份文档只讲片头：歌名、歌手、载体、怎么动起来、怎么验收。
字幕的正片样式归 `subtitle-styles.md`，这里不重复。

> **生成入口已换**：下文的 ImageGen = `media_api.py image`（`hunyuan-image-alpha`，片头场景用 `1920x1080`），
> VideoGen = `media_api.py video`（默认 `kling-video-v3` + `1080P` + `enable_audio=false` + `watermark=false`）。
> 配置与参数见 `references/15-media-api.md`；图生视频首帧必须是公网 URL。
> 文中水印坐标是**旧内置工具**的实测记录，新接口不能照抄——先测 bbox 再决定裁不裁。

## 〇、先记住：片头就是交付文件的第 0–3 秒（2026-10-26 数据回流）

片头不只是"歌名好不好看"，它**就是观众点进来看到的第一眼**。
分镜里评过的"第一镜钩子"在这里会被整段顶掉——所以片头必须自己过钩子关。

实测数据（一条 3:42 纸雕 MV 发抖音几天后）：播放 706（同类中位 47，**算法给了 15 倍试探流量**），
但 2s 跳出 59.94%（中位 39.14%）、5s 完播 15.77%（中位 46.39%）。分发不欠它，死在开头。

抽帧复盘，前 26 秒是这样的：

| 时刻 | 画面 | 问题 |
|---|---|---|
| 0s | **纯黑**（淡入） | 首帧信息量为零 |
| 1–6s | 静态歌名卡，只有字 | 6 秒不动 |
| 6s / 12s | 空房间 / 静物 | 无人、偏暗、信息密度低 |
| 26s | **整墙窗格只有一扇亮着** | 最强图形镜，排在绝大多数人到不了的位置 |

**三条硬要求：**

1. **第 0 帧不许是黑/近黑。** 淡入可以保留，但**淡入起点不能从全黑起**——
   从已有亮度起淡，或干脆去掉开头淡入。`quality_check.py` 会独立查这一项
   （首帧平均亮度 < 25 判不通过），**不受 `--ignore-head` 豁免影响**。
2. **前 3 秒必须有"在动的东西"和"可读的信息"。** 全屏只有一张不动的字牌 = 没有钩子。
   这一点**不自动判定**：实测静态字牌的帧间像素差（1.45–1.65）比正常慢推镜头（0.90–1.11）
   还高（纸面纹理会闪），数值分不出"无聊的静止"和"好看的慢推"。**抽 0s / 1s / 3s 三帧人工看。**
3. **概念要在前 3 秒说出来。** 一行字就够，例如「全程纸雕 · 没有一帧实拍」。
   观众不需要先听完前奏才知道你在做什么。

### 槽位不动：只换内容，不改时长（用户硬约束）

**音频必须是完整原曲，不许二次剪辑、不许缩短、不许拆条。**
所以"把片头从 6 秒压到 3 秒"这类建议**一律不要提**——那会让后面整段前奏的
素材排布全部重算，剪辑难度反而上升。

正确做法是**保留片头原有的时长槽位，只换里面的内容**：

| | 旧做法 | 新做法 |
|---|---|---|
| 时长 | 6 秒 | **6 秒（不动）** |
| 位置 | 时间轴最前 | **时间轴最前（不动）** |
| 内容 | 静态字牌 + 歌名 | **强图形镜 + 慢推 + 歌名压在画面里 + 一行概念字** |
| 音乐 | 原曲 | **原曲（不动）** |

**代价只有一个片头片段的重新生成**，后面所有镜头一帧不用动。
选"强图形镜"时优先从正片里挑：本片最合适的就是那个窗格镜——
构图几何、明暗对比强、一眼能认出"这是纸做的"。

## 一、一条铁律：片头信息不是字幕层

**不能**用 ASS 字幕把一个"写着歌名的卡片"叠在画面上。哪怕它很好看。

理由不是洁癖，是三条一眼就假的症状：

| 后期叠上去 | 长在画面里 |
|---|---|
| 镜头推近，字纹丝不动 | 字跟着画面一起放大 |
| 纸在飘，字钉死在屏幕上 | 字随纸一起摆 |
| 纸有透视和褶皱，字是正面平的 | 字贴着那个面走 |

**反面教材（本 skill 真实踩过）**：给一首夜戏 MV 做片头，用 ASS 画了一块
790×286 的米色纸牌压在画面正中，位置 y=470。结果：

- 纸牌盖住了整个纸雕场景的中央，观众第一眼看到的是一块白板
- 推镜时牌子是死的，和画面分离
- 用户的原话：「这个标题太丑了而且遮挡了大部分的内容」

同一套做法在暖米色日景里能勉强成立（纸牌和画面同色系），**在暗调画面里必定崩**。
所以不要有"这次应该也行"的侥幸。

## 二、先选版式：字怎么和场景待在一起

### 先说清楚：为什么"一块纸 + 大字"会显得单调

最常见的翻车：把纸幡当主体，让它占画面 60–85%，于是**场景被挤没了**，画面只剩一张纸。
再配上"标题 + 署名"两级排版，就成了一张 PPT。

真正高级的片头（报刊封面那种质感）有三个共同点：

1. **场景是主角**，字只是压在场景上的一层——观众先看到"一个地方"，再意识到上面有字
2. **有编辑层次**：眉标、主标、细线、出处，四件套撑起"这是一张出版物"的感觉
3. **字是印上去的**：纸纹调制、柔影、微模糊，不是浮在画面上的矢量字

### 两种版式，二选一

| | **A 压字型** | **B 纸带型** |
|---|---|---|
| 长相 | 场景满幅，字直接压在画面中部 | 场景占上部 72–78%，底部纸带承字 |
| 参考 | 《手写的从前》 | 《大梦归》 |
| 适合 | 画面本身有留白/暗部 | 画面很满、没有安静区域 |
| 字色 | 暗底用暖米 `#F2E2C4`，亮底用暖墨 `#2B2118` | 纸带上一律暖墨 |
| 主标字号 | 画面宽的 **55–72%**（6 字约 170–190px） | 纸带高的 **55–65%** |
| 场景占比 | 100%（字压在场景上） | 72–78% |
| 风险 | 背景太花会读不清 | 纸带颜色跳戏 |

**判据**：底图的中部（画面 35–65% 高度）有没有一块"安静"的区域？
有 → A；没有 → B。

#### A 压字型的排版参数

```
主标   字距 0.06em，居中，中心落在 46–52% 画面高
眉标   歌手名，0.23×主标字号，主标上方 0.16H，字距 0.12em
细线   主标上方再 0.02H，宽 150–300px，1.5px，暖墨 40% 透明
柔影   blur 8–10px，下偏移 3px，强度 0.55–0.75（暗底要更重）
字色   暗底 #F2E2C4 / 亮底 #2B2118，都不用纯黑纯白
```

#### B 纸带型的排版参数

```
纸带   高 22–26%，色取画面同族纸色（暖米 #F0E7D4 一类），上沿一道 8px 软影
主标   居中，中心落在纸带 40–45% 处
细线   主标下方 0.30×纸带高，宽 300px，砖红或暖墨 55%
出处   细线下 0.10×纸带高，0.23×主标字号，「歌手 · 《歌名》主题曲」
```

### 载体还要不要

要，但**不再当主体**。载体退成两种用法：

- 贴在场景里的**一块小牌子/一张纸**，占画面 15–25%（当画眼，不当背景）
- 或者干脆不用载体，字直接压在场景上（A 型）

**判断标准**：把字全去掉，画面还成不成立？成立才说明场景在，而不是"为了放字而搭的台子"。

### 署名放哪里：歌名居中，但署名可以拆出去

"文字块居中"说的是**歌名**，不是"歌名+歌手"拼成的那一大块。两者混为一谈，换个画面就翻车。

实测案例：片头正中立着一座钟楼，表盘落在 (975, 420–500)。按"整块居中"把歌名和署名一起下移，
40px 的"周杰伦"正好压在表盘刻度上——深色小字叠深色指针，手机上读不出来。

正确的解法不是把标题挪走（那就不居中了），而是**把署名从标题块里拆出去**：

| 元素 | 位置 | 理由 |
|---|---|---|
| 歌名 | 中心 y≈556（画布中线 540，低 16px） | 视觉居中；略低于中线反而更稳 |
| 署名 | y=292，歌名上方 260px 的天空带 | 做眉标，避开实体，不破坏居中 |
| 分隔线 | 去掉 | 压在云层里等于没有，还添乱 |

**判据**：画布中心 ±120px 内若出现高对比实体（钟楼、人脸、招牌、强边缘），
不要再把署名塞在标题旁边，按这个顺序选位置：

1. **标题上方的干净带**（首选，做眉标）
2. **画面下沿做小字幕 36–40px**（次选，最稳，但要确认不压主体）
3. 标题左右两侧的空带（最后，破坏对称，慎用）

**实测参数**（1920×1080，5 字标题）：

```
字号 196 / 字距 22   →  宽 1068px = 55.6%（贴着上限；超过 58% 就显得满）
标题实际像素 y = 468..649（中心 556）
署名 40 / 字距 14，y = 292
柔投影 blur 9 / alpha 130，偏移 +8px
推镜 1.00 → 1.07，锚点锁画面中心
```

**推镜的副作用要知道**：`zoompan` 以锚点为中心外扩，`out_y = 540 + (y-540)*z`。
放在中线附近的元素几乎不动（556 → 555），离中线越远位移越大。
所以"居中"不只是好看，它还能让标题在推镜过程里保持稳定。

```python
# 按墨色相似度量标题实际位置，比灰阶阈值可靠
im = np.asarray(Image.open(f).convert("RGB"), dtype=int)
band = im[:, 420:1500]                            # 只取横向中段，避开两侧深色纸影
d = np.abs(band - np.array([48, 34, 24])).sum(2)  # 标题墨色
rows = np.where((d < 45).sum(1) > 60)[0]          # 每行超过 60 个墨色像素才算字
print("标题 y=%d..%d 中心 %.0f" % (rows.min(), rows.max(), (rows.min() + rows.max()) / 2))
```

⚠️ 别用"灰阶 < 100"当判据：纸雕的屋檐阴影、门洞、深色纸边都会中招，
实测量出"占宽 99.5%"这种完全失真的数字。

**改完片头必须同步重制无字幕母版**，否则下次改字幕时烧的还是旧标题：

```bash
# 新片头（125 帧）+ 母版去掉前 125 帧，一次编码拼回
ffmpeg -y -i out/title_v2.mp4 -i out/base.mp4 -filter_complex \
  "[1:v]trim=start_frame=125,setpts=PTS-STARTPTS[b];[0:v][b]concat=n=2:v=1:a=0[v]" \
  -map "[v]" -c:v libx264 -crf 18 -preset medium -pix_fmt yuv420p -an \
  -t 291.75 out/base_titled.mp4
```

## 三、三段式：出无字场景 → 排字 → 让它动

### ① 文生图出**场景**（`media_api.py image`）（不是"一块广告牌"）

**别再写 `a blank signboard filling 60% of the frame width`** —— 这句话就是在生成"一张纸"，
生成出来必然单调。要写的是**一个有故事的空间**，并给它留出安静区。

#### A 压字型的提示词

```
cinematic wide shot of <场景：一条纸做的夜巷 / 一片纸山 / 一间亮着灯的屋子>,
handcrafted paper-cut diorama, tilt-shift macro photography, deep indigo night,
warm amber window lights, dust motes in the air, shallow depth of field,
the middle band of the frame (35–65% height) left VISUALLY CALM and uncluttered
so a title can sit on it, subject placed off-centre,
absolutely no text, no letters, no characters, no signage, no logo, no watermark
```

#### B 纸带型的提示词

```
cinematic wide shot of <场景>, handcrafted paper-cut diorama,
the scene occupies the UPPER THREE QUARTERS of the frame, rich in detail,
the BOTTOM QUARTER is a plain sheet of cream handmade paper with visible fibre
texture, completely empty and clean, reserved for a title,
deep indigo night, warm amber lights, dust motes,
absolutely no text, no letters, no characters, no signage, no logo, no watermark
```

#### 三条必写

1. **`VISUALLY CALM / empty` 指明哪一块留给字** —— 不写它就会把整个画面塞满
2. **`subject placed off-centre`（A 型）** —— 主体居中会和标题打架
3. **`absolutely no text`** —— 正反向都写，否则模型自己加字

> 出图后先别看字：**把图当成一张纯风景看，好不好看？**
> 不好看就说明场景没搭起来，重出图，别急着排字。

### ② 用字库把字排进去（`scripts/make_title.py`）

字库排 = 零错字。比让模型画中文靠谱一个数量级，尤其是署名这种小字。

> **为什么封面可以直出、片头却要字库排？** 两者的容错不一样：
> 封面是**一张静态海报**，出图规则全按 `07b-cover-brief.md`，模型直出还能让字跟着褶皱走；
> 片头是**要动起来的 6 秒**，竖排 6 字 + 小署名 + 被推轨带着走，一旦模型丢了字或加了料，
> 整段视频得重生成。片头走"字库排进首帧、模型只负责运动"，字就永远不会错。

**A 压字型**（底图是一整幅场景，字直接压上去）：

```bash
python scripts/make_title.py --src images/title_scene.png     --title "无人知晓的我" --singer "A-Lin" --cy-title 545 --singer-y 350     --singer-size 40 --no-line --still out/title_still.png
```

`--cy-title` 是主标中心（画面 46–52% 高），`--singer-y` 是眉标的 y。
这两项没有通用值，先出静帧看一眼再调。

**B 纸带型**（底部纸带承字）：

```bash
python scripts/make_cover.py --src images/title_scene.png --title "无人知晓的我" \
    --artist "A-Lin" --layout band --band 0.24 --title-width 0.58 \
    --out out/title_still.png
```

**横排（横幅、信纸、车票）**

```bash
python scripts/make_title.py --src images/plate.png --title "手写的从前" --singer "周杰伦" \
    --cy-title 505 --singer-y 292 --singer-size 40 --no-line --still out/title_still.png
```

`--cy-title` 是歌名文字块的**中心 y**，`--singer-y` 是署名的 y。
这两个数没有通用值——上一支片量出来是 505 / 292（歌名居中偏下、署名作眉标压在塔尖上方），
换一部片必须重新定：先跑 `--no-video` 出静帧，看一眼再调。

**竖排（纸幡、竖招牌）**——这次踩的坑就在这条路上：

```bash
python scripts/make_title.py --src images/plate.png --title "无人知晓的我" --singer "A-LIN" \
    --vertical --area 760,66,1160,622 --still out/title_still.png --no-video
```

`--area x0,y0,x1,y1` 是**载体在源图里的范围**（不是画面范围）。脚本会：

1. 先按"n 个字 + 字距 + 署名"算出能放下的最大字号
2. **强制上下各留 ≥6.5% 载体高**——放不下就自动降字号，一直到装得下
3. 打印实测值：占载体高、首字距顶、末字/署名距底、字块中心与载体中线差

```
竖排 6 字 字号 70  占载体高 86.3%
首字距载体顶 40px（7.2%）  末字/署名距底 36px（6.5%）
字块中心 x=960（载体中线 960，差 -0）
```

> **这一条是这次返工的直接原因**：手写版按载体高度算满（93%），
> 首字顶到纸边 3.6%，用户一眼看到"字跑出去了"。
> 现在留白由脚本强制，不看也会守住；如果字号被降到 40 以下，说明载体本身太小，
> 该回去把纸幡生成得更高，而不是继续挤。

字怎么"压进纸里"（脚本已内置）：

- 用**底图亮度调制墨的不透明度** —— 纸纹处墨淡一点，看起来是吸进去的
- 向下 2px 打一层 35% 的压印暗层
- 0.5–0.6px 高斯，去掉矢量锐边
- 暖墨 `#2B2118`，**不要纯黑**（纯黑在米纸上像贴纸）

### ③ 让这一帧动起来

> ⚠️ **先记住一条：字不能跟着一起交给模型。**
> 把已经排好字的静帧丢给图生视频，模型一定会重绘它。实测 6 秒的片子，到第 5.9 秒
> 「无人知晓的我」**整行消失**，文字带相邻帧差 43.86（其余区间只有 5–9）。
> 正确做法是**把背景和文字分开**：
>
> ```
> 文生图出无字场景 → 图生视频只让这个场景动 → crop_watermark 裁水印（先测 bbox）
> → PIL 画静态文字层（同名衬线、同字号字距）→ ffmpeg overlay 合成 N 帧
> ```
>
> 这样字**由构造保证不动**（一张 PNG 盖 N 帧），画面又有真实环境运动。
> 实测同一个镜头：背景机位 6 秒只漂 1.6px（锁机位成立），画面帧差 1.4–3.8（全程有动）。

**推荐：`media_api.py video` 图生视频**（纸边会颤、灰会飘、窗光会闪，字在第一帧里烫死，不会错）。

```
image      : out/title_still.png
seconds    : 6
resolution : 1080P
audio      : false
prompt     : Locked-off tripod shot, completely static camera. NO zoom, NO push-in,
             NO dolly …（见第四节坑 1）
negative   : zoom in, push in, dolly in, camera movement, warped text,
             changed characters, extra text, cropped banner
```

**备选：zoompan 推镜**（最稳，但只有推，没有环境感）：
`zoompan 1.00 → 1.07 / 125 帧`，锚点放在载体中心。

> **什么时候放弃图生视频**：抽首末帧发现字被推歪、笔画糊掉、或者载体变形——
> 直接退回 zoompan。宁可少一点"环境感"，也不能让歌名在动的时候发抖。

> **片头留 5–6 秒。** 六个竖排字 + 署名，少于 4 秒读不完；超过 7 秒观众会开始等。
> 本次是 5.92 秒（142 帧），前 1.4 秒还在淡入，实际可读约 4.5 秒——刚好。
>
> **但时长合格 ≠ 开头合格。** 上面这个 5.92 秒的版本就是数据翻车的那版：
> 它"读得完"，却"留不住人"——首帧全黑淡入 + 整段只有字在动。
> 时长照第〇节保留不动，要改的是**内容**：首帧有亮度、画面有运动、前 3 秒有概念字。
> **淡入不要从全黑起**，那 1.4 秒恰好是观众决定走不走的窗口。

**生成完立刻走这两步，不做就不许往下：**

```bash
python scripts/crop_watermark.py --src raw.mp4 --out clips/s01.mp4   # 裁水印 + 自动复测
python scripts/check_title.py --clip clips/s01.mp4 --area 760,66,1160,622   # 六项全查
```

不通过就回 `③` 重新生成——**换提示词、换机位写法、换做法都行，就是不许带着缺陷往下走。**

### ④ 切点要匹配：片头不是独立的一段

片头做合格了，剪进片子仍然可能"卡一下"。原因不是切得硬，是**两侧不匹配**。
先量，别凭感觉：

```bash
python scripts/match_cut.py --a work/s01.mp4 --b work/s02.mp4 --outdir work/match
#   切点前：A 末帧均值 45.7  B 首帧均值 71.2  差 25.4
#   切点后：A 末帧 70.7  B 首帧 71.2  差 0.5
#   [通过] 切点已对齐
```

一次实测的失败案例（真实数据）：

| | 片头末帧 | 第一镜首帧 | 落差 |
|---|---|---|---|
| 平均亮度 | 45.7 | 72.3 | **+26.6** |
| 亮部占比（>140） | 4.8% | 20.3% | 4 倍 |
| 空间 | 巷子全景、有纵深 | 桌面微距 | 尺度跳 2 档 |
| 色温 | 靛蓝 + 暖灯 | 蓝灰 + 米纸 + 蓝斜光 | — |

一刀同时跳亮度和尺度两档，观众第一反应就是"卡了一下"。**用户原话：太突兀了。**

#### 为什么不能用 xfade 解决

叠化要吃掉重叠帧数，全片总帧一变，**所有字幕时间点全部错位**。
53 句歌词的 MV 里，这是不可接受的代价。所以改两侧的出入口，帧数一帧不动：

| 手段 | 做什么 | 效果 |
|---|---|---|
| **A 退场加雾** | 末尾 26 帧叠米色雾光（alpha 由 match_cut 解算，实测 0.138） | 末帧 45.7 → 70.7，且"雾涨满"= 场景化进纸里 |
| **B 入场拉焦** | 开头 9 帧高斯虚焦 11px → 0 | 空间尺度跳变变成一次"拉焦" |
| **B 入场轻雾** | 需要时（A 比 B 亮）给 B 加 ≤0.05 米色 | 色温靠拢 |

> **关键坑**：把 A 抬到 B 之后，**不要再给 B 加雾**。两边同时抬，永远追不上——
> 第一版脚本就是这么写的，切完还剩 8.0 的落差，还以为是参数不够。

#### 判据

- 切点亮度差 **≤ 4**（一档以内）→ 通过
- 差 > 8 就得处理；处理不了说明这两个镜头本来就不该硬接，考虑换镜或插入过渡镜
- 抽 5 个点看一遍：切前 0.5s / 切前 0.2s / 切点 / 切后 0.1s / 切后 0.3s

### ⑤ 接回正片（这一步最容易漏）

片头不是独立文件，它要占掉时间轴的第一段，**总帧数必须不变**：

1. 定片头帧数 `N`（24fps 下 6 秒 = 144 帧，5.9s = 142 帧）
2. 把生成片段裁水印、补亮度、转成 `clips/s01.mp4`，`-frames:v N`
3. **从原来的前奏段里切出这 N 帧**（原 3 镜 → 片头 + 2 镜），不要整体加长：
   全片总帧不变，字幕和后面的镜头就都不用动；一旦整体加长，所有时间点全部错位
4. 重新 concat → 重渲 → 跑 `quality_check.py`
5. **成片 mtime 必须晚于字幕文件**，否则你渲的是旧的

> 改片头等于改整条时间轴的第一段：字幕不用动（歌词从 13.0s 才起），
> 但 `shots.json` / `timeline.json` 的前三镜时长要跟着改，否则核对时会以为总长对不上。

## 四、图生视频这条路的六个坑（旧内置工具实测，思路仍适用）

### 坑 1：写 "slow push-in" 它会推过头

第一次提示词写 `Slow cinematic push-in`，6 秒里模型推了约 1.5 倍，
到 5.8 秒时**标题已经被裁出画面**。

改写成锁机位：

```
Locked-off tripod shot, completely static camera. NO zoom, NO push-in, NO dolly,
NO camera movement whatsoever for the entire shot: the framing must stay exactly
identical to the first frame, with the whole banner fully visible and comfortable
dark margins above the bracket and below the banner.
```

negative 挂 `zoom in, push in, dolly in, camera movement, cropped banner, banner leaving frame`。
实测锁机位版本 6 秒全程不出画。

> 但要注意反向的经验：上一版做动画 MV 时，写 `locked-off` 反而被模型**拉远**，
> 标题从 40% 缩到 25%。结论不是"哪个提示词更对"，而是——
> **两版都要抽首尾帧核对**，不许只看第一帧。

### 坑 2：水印位置**不固定**，不许套一个固定的 crop 值

早期文档写死 `crop=1700:956:110:0`（裁掉左侧 110px），这是**错的做法**。实测：

| 来源 | 水印 bbox（1920×1080） | 说明 |
|---|---|---|
| ImageGen 出图 | 右下角 | 3:4 底图裁 `0,0,1024,1365`；16:9 底图裁 `1755:987:0:0` |
| VideoGen（本机） | 左上 **(10, 10)–(127, 63)** | 118×54，裁 110px **会剩 17px 尾巴** |
| VideoGen（另一台机器） | 左上，但更靠右 | 直接套 110px 完全没裁掉——用户实测遇到过 |

**正确顺序：先测，再裁，再复测——一条命令做完：**

```bash
python scripts/crop_watermark.py --src raw.mp4 --out clips/s01.mp4
#   水印 左上角 1.00 @ (10, 10, 127, 63)
#   裁切 crop=1646:1007:137:73（左右各 137，上 73）→ 复测最高分 0.00
#   [通过]
```

它会：①四角逐帧扫出 bbox ②按 bbox 对称裁（左右同宽，保持构图居中）③拉回原尺寸 ④**自动复测**，
残留就返回 2。单独测某一项：

```bash
python scripts/check_title.py --clip clips/s01.mp4 --only watermark
```

**为什么必须复测**：裁完看起来"应该没了"，和实测"确实没了"是两件事。
这个 skill 的片头就因为只做前一步，交付的片子里水印一直在。

### 坑 3：生成片段自己会越来越亮

实测一段 6 秒的夜景：`mean luma 60.7 → 74.4`（雾升起来了）。
接到后面的暗镜头上会像曝光跳了一档。

用逐帧亮度补偿压回去：

```
eq=brightness='-0.056*min(t/5.9,1)':eval=frame
```

系数 = (末帧均值 − 首帧均值) / 255，符号取负。补偿前后实测：

| 时间 | 补偿前 | 补偿后 |
|---|---|---|
| 0s | 60.7 | 67.7（裁切后整体抬高，但这 1.4 秒还在淡入，看不见） |
| 3.0s | 65.0 | 60.3 |
| 5.8s | 74.4 | 60.7 |

可读区间（3s 之后）从 +9.4 的漂移收到 **±0.4**，接到后面的暗镜头不再像曝光跳档。

### 坑 4：别做"对黑"过渡，QC 会判非预期黑帧

片头（亮）接城市远景（暗），中间插了 3 帧对黑，`quality_check.py` 直接判
**"非预期黑帧 1 处"** 不通过。

正确做法：**硬切**。亮 → 暗本身就是一次"揭示"，比过渡更有力。
真要过渡就做叠化（xfade），但叠化会改变总帧数，得在时间轴上先扣掉。

---

### 坑 5：把已排字的静帧交给图生视频 → 字会被重绘掉

**症状**：前 4 秒都好好的，最后一秒歌名"化"进背景，只剩几个残笔。
**实测数据**：文字带相邻帧差 **43.86**（正常区间 5–9），文字质心 y 126 → 100（整行漂了）。
**原因**：生成模型把文字当成画面内容一起重绘。提示词写 `the lettering stays perfectly still`
也没用——它不理解"这是要保留的图层"。
**修法**：字不进模型。见 ③ 顶部的"背景归模型、文字归图层"。

### 坑 6：雾一起来，文字的对比度就掉了

**症状**：开头几帧字很清，越到后面越糊——不是字变了，是**字后面的底变亮了**。
**实测**：薄雾滚到巷子尽头后，中部亮度升高，米色字和米色雾贴在一起。
**修法**：在文字层里加一层**椭圆径向压暗**（峰值 0.22，中心对齐标题带，半径约 780×250）。
注意是径向渐变，**不是纸带**——纸带会把 A 型压字的"字长在场景上"变成 B 型。

## 五、如果片头非要走 ASS（只能用在这两种情况）

1. 片子本来就是**白底/亮底**的图形动画，没有"画面里的纸"可以承载
2. 用户明确要求"标题卡"这种版式

此时必须注意：`BorderStyle=3`（色块底）配 `Shadow>0` 时，libass 会在字块**外面**
再画一层带偏移的暗色矩形，看起来像多了一个框。

修法：把 `Shadow` 颜色的 `\4c` 设成**和纸牌同色**，让它隐形；或者干脆 `\shad0`。
（本 skill 第一次就栽在这——片头牌子上莫名多了一圈深色描边。）

## 六、验收：跑脚本，不过就重做

**片头不允许"看着差不多"就拼进时间轴。** 一条命令查六项，退出码 2 就是不合格：

```bash
# B 纸带型（有载体可量）
python scripts/check_title.py --clip clips/s01.mp4 --area 760,66,1160,622
# A 压字型（无载体，只查水印与时长，版式人工抽帧）
python scripts/check_title.py --clip clips/s01.mp4 --layout overlay
```

| 项 | 门槛 | 脚本能查 |
|---|---|---|
| 水印 | 四角任一检出即不合格 | ✅ |
| 时长 | 4.5–7.0s | ✅ |
| 首字留白 | ≥ 载体高 6.5% | ✅ |
| 占载体高 | 60–87% | ✅ |
| 居中 | 字块中心 = 载体中线（±8px）= 画面中线（±8%） | ✅ |
| 出画 | 首末帧载体都完整在画面内 | ❌ 人工抽两帧 |

> **人工只剩两件事**：抽首帧和末帧看出画、读一遍人名有没有写错。
> 其余全部交给脚本，别靠眼睛。

### 不合格怎么办（按顺序试，不设次数上限）

| 症状 | 处理 |
|---|---|
| 水印还在 | 回到坑 2：按检测出的 bbox 重裁 → 复测 |
| 首字贴边 / 占比不对 | 重跑 `make_title.py --vertical`（会强制留白）；还不行说明载体太小，回文生图把纸幡生成得更高 |
| 字被推歪、笔画糊、载体变形 | 换 `locked-off` 提示词重生成视频；仍不行退 zoompan |
| 时长不对 | 改 `-frames:v N` 重出 |
| 字错 / 多出物料 / 主体跑了 | 底图重生成，重新排字 |

**每一轮都重跑 `check_title.py`，直到 `exit 0`。**
不要因为"已经重做了三次"就放行——放行的代价是整片带缺陷交付。

### 为什么这条要写死

真实事故：片头在另一台机器上生成，水印位置比本机靠右，按固定 110px 裁完恰好留了半截；
同时没有任何强制验收，结果**带着水印的片头直接进了成片**。
所以这里不是"建议检查"，是**不过不许往下走**。

## 七、一句话总结

> 片头不是"把字排上去"，是**给这首歌找一张纸，把名字写在上面，再让这张纸被镜头看见**。
> 字库负责不出错，模型负责让它动起来，人负责核对它有没有出界。
