# 第一步：素材分析 → 风格候选 → 样张确认

**在写任何提示词之前，先把手上有什么搞清楚。** 这一步产出一张"意象表"和 3 套风格候选，
后面 90% 的提示词都从这两样东西里长出来。

---

## 一、先盘点输入

| 输入 | 必给 | 怎么用 |
|---|---|---|
| 音频（mp3/m4a/wav） | ✅ | 定 BPM、段落、情绪曲线、总时长 |
| 歌词（txt/lrc/docx） | ✅ | 断句、抽意象、定分镜数量 |
| 参考 MV（mp4） | 可选 | 读风格参数、镜头节奏、字幕样式——**参考不是抄** |
| 已有素材（图/片段） | 可选 | 能复用的直接进时间轴，不重新生成 |

### 先跑三条实测（不许估）

```bash
python scripts/mediainfo.py assets/ -o out/manifest.json
python scripts/song_structure.py --audio song.m4a -o out/structure.json
python scripts/beat_sync.py song.m4a -o out/beats.json
```

`song_structure.py` 会给：段落（主歌/预副歌/副歌/桥/尾）、BPM、每段强度、
建议单镜时长与镜数、**预估 credits**。把这个数先报给用户，别闷头开工。

---

## 二、如果用户给了参考 MV

不要"看一眼找感觉"，要读出可复用的参数：

```bash
# 每 10 秒抽一帧，拼成联系表（人眼读视觉语言）
ffmpeg -i ref.mp4 -vf "fps=1/10,scale=320:-1,tile=6x4" -frames:v 1 out/ref_sheet.png

# 如果参考片自带硬字幕，直接读它的字幕样式参数
ffmpeg -copyts -ss 12 -i ref.mp4 -frames:v 1 out/ref_sub.png
```

读这四件事，写进 `out/brief.md`：

1. **调色**：主色 hex、冷暖、对比度（高对比还是灰调）
2. **材质**：实拍 / 纸 / 布 / 3D / 插画
3. **镜头节奏**：平均单镜几秒（副歌段单独量）
4. **字幕**：有没有底框、字号占宽多少、字色、逐字还是一次出

> **参考的正确用法**：用户说"要这种感觉"，你读出的是参数（暖黄、纸质、3.2 秒一镜、
> 纸卡字幕），而不是"照着这个再做一遍"。

---

## 三、从歌词里抽"意象表"

这是整条链路最容易被跳过、也最值钱的一步。**每一句歌词都要能落成一个可拍的东西**，
落不成的句子，就是最后成片里"配了一张风景图"的地方——也是观众划走的地方。

做法：逐句问四个问题，填成表。

| 歌词 | 物件 | 空间 | 动作 | 光 |
|---|---|---|---|---|
| 有些话不知道要怎么说 | 一张纸 / 一个字条 | 桌边、窗前 | 手停住、纸被捏皱 | 台灯侧光 |
| 固执的自转陀螺 | 纸陀螺 | 桌面、空房间 | 高速旋转、慢慢失衡 | 顶部一束光 |
| 那城市的高楼是土地的瘤 | 纸做的楼群、根须 | 地面往上长 | 楼从土里顶出来 | 冷白 + 暖窗 |

```json
{
  "line": "固执的自转陀螺",
  "object": "paper spinning top",
  "space": "empty tabletop, dark room",
  "action": "spinning fast, slowly losing balance",
  "light": "single beam from above"
}
```

**判定标准**：一行的四个格子都填得出来，这句就能拍；某个格子空着，
说明这句需要一个"替代意象"——去歌词里找前后句的物件来借。

## 四、风格选项：给用户 5 个，并明确标出推荐

**这一关不花 credits。** 用户靠文字就能做判断，不要一上来就烧图。

```bash
python scripts/style_advisor.py --list                                  # 31 套，10 个家族
python scripts/style_advisor.py --audio song.m4a --lyrics lyrics.txt    # 出跨家族候选
```

取 **5 个不同家族**的候选（同家族只留最强的一个，否则选项没有区分度），
按 `references/02-scoring.md` 的 L1 卡打分，再换算成推荐度：

| 总分 | 推荐度 | 含义 |
|---|---|---|
| ≥4.5 | ★★★★★ | 主推，可以放心走 |
| 4.0–4.4 | ★★★★ | 强烈备选 |
| 3.5–3.9 | ★★★ | 可行，但有明确短板 |
| 3.0–3.4 | ★★ | 只在用户坚持时用 |
| <3.0 | ★ | 别放进来占位 |

### 给用户的选项卡（照这个格式给，不许只给名字）

```
【风格选项 · 请选一个，或回复"按推荐"】

★ 推荐  A. 纸雕夜城            ★★★★★ 4.6
        暗色纸 + 背后暖光，孤独但有温度；和你这首歌的"被忽视"完全同频
        出图稳定：单主体、无文字、无多人，40 镜预计重试 6 次
        成本：≈3700 credits / 2–4 小时

      B. 厚涂插画              ★★★★ 4.1
        手绘笔触、情绪浓，但同风格不同镜头容易笔触不一致
        出图稳定：一般，重试率约 25%（+900 credits）

      C. 剪影动画              ★★★★ 3.9
        ...
```

### 三条硬要求

1. **必须有推荐度，且第一名要标出来。** 让用户在"有依据的建议"上做选择，不是在五个名字里瞎挑。
2. **每个选项都要写代价**：重试率、credits、时长。用户才能判断值不值。
3. **必须等用户回复。** 用户说"按推荐"才直接采纳；说"再给几个"就换家族重出。

选定后把风格后缀（style suffix）抄进 `style.md`，**后面每一条提示词原样带上**——
这是全片风格统一的唯一保证。

## 五、样张：用选定的风格出 3 张，迭代到用户说"可以"

**注意：样张不是用来比风格的，是用来验证这一个风格撑不撑得住整部片。**
所以 3 张要覆盖三种镜头类型，不是三个风格各一张（那样等于把关1 又做了一遍）。

| 张 | 镜头类型 | 挑哪句 | 验证什么 |
|---|---|---|---|
| 1 | **主体特写** | 副歌最重的一句 | 风格在近景会不会糊、材质经不经得起放大 |
| 2 | **空镜 / 环境** | 主歌的铺垫句 | 没有主体时画面会不会空、光够不够 |
| 3 | **情绪镜** | 桥段或尾句 | 明暗对比、情绪能不能顶上去 |

```bash
# 拼对比图给用户（3 张横排）
python - <<'PY'
from PIL import Image
import glob
fs = sorted(glob.glob("out/samples/*.png"))[:3]
w, h = 480, 320
sheet = Image.new("RGB", (w*len(fs), h), (16,17,21))
for i, f in enumerate(fs):
    sheet.paste(Image.open(f).convert("RGB").resize((w, h)), (i*w, 0))
sheet.save("out/style_samples.png")
PY
```

### 迭代规则（这是最容易做错的地方）

```
用户说"可以"        → 锁 style.md，进第 ④ 步（剧情方案）
用户说"不行"        → 问清楚改哪一项，只改这一项，重出 3 张
用户说"再试试别的"  → 回第四节换风格，不要在当前风格上硬调
```

**一次只改一个维度**：更暖/更冷、更密/更空、换材质、字更重。
同时改三项，用户说不清哪个起了作用，下一轮还是瞎猜。

**最多 3 轮。** 3 轮还不对，说明风格本身选错了——回关1，别在这里耗。
每一轮把改动记进 `style.md` 的"迭代记录"，否则第 4 次重来时你又从零开始。

**成本账**：3 张 ≈24 credits，40 镜返工 ≈3000 credits。**先花小钱验证方向，再花大钱执行。**

## 六、这一步的交付物

```
out/
  brief.md          素材分析 + 参考片参数 + 意象表
  structure.json    段落/镜数/预估 credits
  beats.json        拍点
  style.md          锁定风格 + style suffix + L1 打分表 + 迭代记录
  style_samples.png 选定风格的 3 张样张（已获用户确认）
```

**没有 style.md、或样张没被确认，就不要进下一步。**

> 样张确认之后**直接进剧情方案，不再单独出视频样片**——视频的质量靠批量后逐镜抽首末帧把关
> （见 `03-generation.md` 第四节）。所以这一关必须看仔细：它是批量前唯一一次目视确认。
