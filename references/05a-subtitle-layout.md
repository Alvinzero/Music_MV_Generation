# 字幕布局：逐镜适配

字幕不是"顶 / 中 / 底"三选一。**同一个片子里，每一句的字幕位置和字号都应该不一样**，
因为它们落在不同的画面上——有的画面主体在中间，有的在底部，有的整幅都是人。

固定一行字幕反复出现在同一个高度，本质上是把字幕当成"覆盖层"；
正确的做法是把它当成**画面里的一个元素**，去找那块本来就空着的地方。

---

## 一、先摆画面，再摆字幕

字幕只有一个硬约束：**不许压主体**。

主体包括：

- 人脸（最重要，压脸一帧都不能忍）
- 正在做动作的手 / 乐器 / 道具
- 建筑中轴（钟楼、门框、雕塑这类构图重心）
- 人群密度最高的那块区域

主体之外的一切——天空、地面、空墙、桌面、远景虚焦——都是可用的。

> 常见错误：整片用"底部居中"，遇到"人物躺在画面底部"的镜头就会压脸；
> 改成"顶部居中"，遇到"仰拍钟楼"的镜头又会压塔尖。
> 所以必须**逐镜看**，不能全局定一个值。

---

## 二、三步法

### 第 1 步：按每句中点抽帧

字幕时长通常和一句歌词等长，取中点那一帧最能代表整句的画面。

```bash
python - <<'EOF'
import json, subprocess, imageio_ffmpeg
FF = imageio_ffmpeg.get_ffmpeg_exe()
for n, it in enumerate(json.load(open("out/lines.json")), 1):
    t = (it["start"] + it["end"]) / 2
    subprocess.run([FF, "-y", "-v", "error", "-copyts", "-ss", str(t),
                    "-i", "out/base.mp4", "-frames:v", "1", f"qa/lines/L{n:02d}.png"])
EOF
```

再拼联系表，一次看 12 帧：

```bash
ffmpeg -y -start_number 1 -i qa/lines/L%02d.png -frames:v 1 \
  -vf "scale=480:270,tile=3x4:padding=4:margin=4" qa/lines/S1.jpg
```

> `-copyts` 必须加。不加的话 `-ss` 之后时间戳从 0 重新计，字幕滤镜会以为这是片头，
> 什么都不画，你会误判成"字幕没生成"。

### 第 2 步：在帧上判空档

对每一帧问三个问题：

1. 主体在哪？（框出人脸和主要动作的范围）
2. 剩余空间里，哪一块最完整、最不打断构图？
3. 这一块的**可用宽度**够放几个字？

常用落点，按优先级：

| 落点 | 适用 | 注意 |
|---|---|---|
| 主体正下方的地面 / 桌面 | 人站着、站着走路、坐着 | 别压到脚和投影 |
| 主体上方的天空 / 空墙 | 仰拍、躺姿、低机位 | 别压到头顶和建筑尖顶 |
| 画面一侧的空白 | 主体偏左/偏右、特写 | 优先选留白更宽的一侧 |
| 两个主体之间的空隙 | 双人对峙、对坐 | 空隙窄时要缩字号 |
| 建筑中轴的两侧 | 对称构图（钟楼、大门） | 宁可拆成两段，也不要横穿中轴 |

### 第 3 步：写进 lines.json

```json
{"start":68.0,"end":73.0,"text":"躺在你学校的操场看星空","x":1250,"y":565,"fs":56}
```

- `x` / `y`：**整行的中心点**（不是左上角）
- `fs`：该句字号
- 三个字段都可省，省了退回 `place`(T/M/B) 与默认 84

---

## 三、字号：装不下就降一档

纸片宽度 = `fs + 2×纸边`，纸边 ≈ `fs × 0.26`。所以：

| fs | 单字占宽 | 字缝 | 一句 10 字约需 |
|---|---|---|---|
| 84 | 128 | 12 | 1388 |
| 76 | 116 | 10 | 1250 |
| 72 | 110 | 10 | 1190 |
| 68 | 104 | 9 | 1121 |
| 64 | 98 | 9 | 1061 |
| 56 | 86 | 7 | 923 |
| 52 | 80 | 7 | 863 |

判定：`可用宽度 ≥ 字数 × 单字占宽 + (字数−1) × 字缝`，否则降一档再算。

经验值：

- 满幅底部行：84（手机上也读得清）
- 主体下方有 800–1000px：76
- 挤在两个人之间 / 一侧窄空白：64–68
- 只有 900px 左右的天空缝：56
- 画面已经被主体占满（躺姿、大特写）：52，贴着画面最下沿

> 宁可小一点，也不要糊在人脸上。观众能读到字的前提是**先看清画面**。

### 无底框墨字：字号怎么算、描边怎么跟

水墨/古风这类**不做纸卡**的字幕（字直接压在画面上、靠纸色描边分离），换算关系完全不同：

```
单字占宽 ≈ 0.66 × fs      墨高 ≈ 0.70 × fs     （思源宋体固化实例实测，换字体要重量）
整句宽 ≈ 字数 × 0.66 × fs
```

| fs | 单字占宽 | 10 字整句 | 占 1920 宽 |
|---|---|---|---|
| 68 | 45 | 450 | 23% |
| 84 | 55 | 550 | 29% |
| 102 | 67 | 670 | 35% |
| 120 | 79 | 790 | 41% |

所以"把字幕放大 1.5 倍"就是 `fs × 1.5`（68 → 102），别按视觉估：
这套字体的占宽只有 0.66em，看着比同号黑体小一圈。

**描边必须跟着字号走**，否则一放大就压不住背景：

| fs | Outline | Shadow | 纸色描边不透明度 |
|---|---|---|---|
| 60–70 | 2.2 | 1.1 | 73%（`&H46`） |
| 80–95 | 2.8 | 1.6 | 80%（`&H38`） |
| 100–130 | 3.4 | 2.0 | 84%（`&H30`） |

大字句（`mode:"scene"` 那几句）再各加 0.3–0.6，因为字更大、也常落在墨块或夜空上。

> 深墨字压在墨块上是**描边**的活，不是颜色的活。别把字改成白色去凑对比度，
> 一改整句就从画面里跳出来了。暗到底的镜头（平均亮度 <0.45）才整句切浅色样式。

---

## 四、什么时候拆成两段

两种情况：

1. **超过 12 字**——脚本自动均分，不用管。
2. **一句话横穿构图重心**——比如正面仰拍的钟楼、对称的大门、正中的单人特写。
   这时可以把一行拆成两组，分别塞进左侧和右侧的空白。

拆段要在 `lines.json` 里写成两条记录（时间首尾相接），不要指望一条记录自动左右分栏。
两条记录的 `x` 分别给左右两侧的中心，`y` 可以不同（跟随各自那侧的空档高度）。

---

## 五、时间轴与位置的耦合

一句歌词可能横跨两个镜头。这时位置要**照顾时长更长的那一镜**，
或者选一个两镜都成立的位置（通常是画面最下沿的窄条）。

判断方法：看这句的 `start`/`end` 各落在哪个 `bounds` 区间里，取覆盖时间更长的那个镜头的构图。

---

## 六、卡片本身长什么样

位置解决了"放哪儿"，还有"长什么样"。参考片里最耐看的一套是**逐字纸卡**：

| 项 | 值（1080p） | 说明 |
|---|---|---|
| 卡片高度 | ≈ 字号 × 1.5 | 字号 66 → 卡 98px；720p 下量到 65px，×1.5 即 1080p |
| 纸面色 | `#F7EFE3` | 偏暖的米白，不是纯白 |
| 字色 | `#4A4244` | 暖墨色，不是纯黑 |
| 高亮卡 | `#E7AA9C` + 米色字 | 珊瑚粉，标记该句的重点字 |
| 投影 | `#C4BAB0`，偏移 3px | 深场里自然变成一圈柔光 |
| 倾斜 | ±2.8° | 每字随机，固定种子，保证每次渲染一致 |
| 纵向错落 | ±6px | 让一行不落在同一条基线上 |
| 字间 | **−6px** | 负值，让纸卡彼此叠压，像手摆的 |
| 出现方式 | 缩放 88→100，80ms | 逐字弹，不是整行淡入 |
| 生长方向 | 左端定死，向右长 | 先算整行最终宽度，把左端放在"长成后仍居中"的位置 |

四个容易做错的地方：

1. **别整行一起出现**。逐字跟着唱走，是这套风格成立的前提。
2. **别让字号全句统一**。一句里挑一个关键字放大到 1.3–1.5 倍，重音才立得住。
3. **别用无衬线**。这套风格的"印刷感"来自宋体——细横粗竖、有衬脚。
4. **别把卡片排成等距**。等距会立刻变成"字幕条"，失去手摆的质感。

> ASS 只能画矩形卡，做不出撕纸毛边。用**倾斜 + 纵向错落 + 负字距叠压**逼近，
> 远看已经很接近；真要毛边得走 `\p1` 矢量或直接烘进画面。

### 怎么"逐帧学习"一支参考片

不是看一遍，是量出来：

```bash
# 1) 每 2 秒一张，看整体排版策略（横条/竖排/散落）
for t in $(seq 0 2 56); do ffmpeg -y -ss $t -i ref.mp4 -frames:v 1 f$t.png; done

# 2) 定位一句字幕，按 0.2 秒连抽 8–12 帧，看它是整行出现还是逐字堆
for t in $(seq 23.0 0.2 25.0); do ffmpeg -y -ss $t -i ref.mp4 -frames:v 1 k$t.png; done

# 3) 放大 3–4 倍裁一个字，量纸面色/字色/卡高
ffmpeg -y -i f24.png -vf "crop=560:110:280:585,scale=1680:330" z.png
```

要量的是：**卡片像素高度、纸面与字的色值、有没有高亮色、字距是叠压还是留缝、
一行是左端固定向右长还是整体居中、一句里字号是否变化**。
这六项定下来，风格就能复现。

## 七、字幕要和画面联动（最容易被忽略的一条）

前面六节解决的是"字幕放在哪、长什么样"。但真正拉开差距的是这一条：
**字幕应该看起来属于这个画面，而不是贴在上面。**

参考片里最典型的一处：14.2–16.3 秒唱"广袤无垠的大海"，画面是一片海。

| 项 | 其他句子（对话场景） | 这一句（海景） |
|---|---|---|
| 介质 | 米白纸卡 | **没有卡**，字直接压在画面里 |
| 颜色 | 暖墨 `#4A4244` | **深蓝 `#2D4A6B`**，取自海面 |
| 字高@720 | 56px | **119 → 157px**（边唱边长） |
| 横向跨度 | 200–400px | **1000px**，横贯画面 |
| 描边 | 无（靠卡片分离） | **一圈浅色描边**，从天空里浮出来 |
| 字重 | 常规 | 明显加粗 |

一句话：**这句话本身变成了海的一部分**——颜色、尺寸、材质全部向画面靠拢。

### 什么时候该联动

判断标准是"这句词和这个画面是不是同一件事"：

**该联动**：画面开阔、色块单纯、词本身是大词
- 海、天空、雪原、星空、逆光、大片纯色背景
- 词是"广袤""无垠""星空""人海""远方""一整片"这类

**不该联动**：画面拥挤、信息密度高、词是日常对话
- 室内、近景特写、多人场景、快速剪辑
- 词是"你吃饭了吗"这种，放大反而可笑

### 明暗方向相反，按背景定

- **亮而开阔**（海/天空/雪）：撤卡 → 字取**场景的暗色**（海的深蓝、山的墨绿）→ 放大 2–3 倍 → 加**浅色**描边
- **暗而开阔**（星空/夜景）：撤卡 → 字取**场景的亮色**（星光、月光）→ 加**暗色**描边
- **中调而拥挤**（黄昏街道、人海俯拍）：撤卡 → 字取**更深的同色系** → 加**米色**描边

一句话：**字色取这块背景的反色，描边取背景的主色**。搞反了就糊成一片——
深蓝字放在深蓝夜空上必看不见。

### 密度：一首 4 分钟的歌，4–5 处

不是越多越好。经验值大约**每分钟一处**，并且要落在副歌或情绪顶点。
判断顺序：

1. 这句词是不是"大词"（星空、人海、远方、广袤、总有一天）
2. 这个镜头是不是"开阔画面"（有天空/远景/大片单色）
3. 这一处是不是全片还没用过联动（别连着三句都用）

三条都满足才用。本站实测：4 分半的歌用了 4 处，分别在 1:12、1:36、3:00、3:53——
间隔均匀，每次出现都换一种底色，观众才不会看腻。

### 实现

`lines.json` 里加 `"mode": "scene"`，并给出取色：

```json
{"start":68.0,"end":73.0,"text":"躺在你学校的操场看星空","x":960,"y":600,
 "fs":104,"mode":"scene","ink":[228,213,196],"edge":[10,43,82]}
```

- `ink`：字色，取**这块背景的主色**
- `edge`：描边色，取背景的反色（亮底给暗描边，暗底给亮描边）
- `fs` 上限 ≈ `1860 / 字数 / 1.06`——字数越多越放不大，这也是为什么参考片
  选的是 7 个字的句子

脚本会自动套用 `S{fs}` 样式（BorderStyle=1：只有描边和投影，没有纸卡），
入场改成单纯的淡入，不再有卡片那种弹跳。

### 更高一层：词义驱动

材质联动是"整句跟着画面走"。再往上一层是：**这个字怎么显示，由它是什么意思决定**。
参考片里有四个层次，越往下越抓人：

| 层次 | 字义 → 什么 | 实例（实测） |
|---|---|---|
| 颜色 | 词的意象 → 色 | 唱到"光明"，那两个字当场从米白 `#F2EBE1` 变成阳光暖金 `#EED6AA`（R−B 从 18 跳到 72） |
| 动作 | 词的动词 → 运动 | "收集"——字被拆成纸屑又收拢；"挫败"——字跟着拼图一起掉；"起"——字飘到人肩头 |
| 载体 | 词的名词 → 物 | "情话"→ 四个字各挂一只孔明灯，沿烟花弧线斜排 |
| 层级 | 主句 → 大道具 | 大字留在天上当标题层，小卡在下面接歌词层 |

做颜色这一层最划算：不用改排版，只要**给某几个字换卡面色**。

```json
{"start":74.0,"end":79.0,"text":"教室里的灯还亮着你没走","x":960,"y":1012,"fs":64,
 "tints":[{"from":4,"to":6,"paper":[238,214,170],"ink":[96,66,34]}]}
```

`from`/`to` 是字下标（含两端）。上例让"灯 还 亮"三个字变成暖光色，
其余保持米白——正好对应画面上亮着的那扇窗。

三条经验：
- **只染关键词**，一句最多 2–4 个字，染多了等于没染
- 染完**后面的字要不要跟着暖**看词义：像"光明起来"是状态延续，就一路暖到句尾
- 暖色卡上的字色要同步加深（浅卡配深字，如 `#604222`），否则字压不住卡

### 动作层与载体层：让字变成东西

颜色只是第一层。再往下是**动**和**形**：

**动作**（`move`）——给字一条位移轨迹：

```json
{"start":243.0,"end":250.0,"text":"当你收到情书 也代表我已经走远","x":520,"y":1012,"fs":56,
 "hold_end":251.6,"move_i":[12,13],
 "move":{"d0":[0,0],"d1":[186,30],"frz0":-2,"frz1":16,"dur":1400,"t0":250.15,
         "fade":[80,520],"scale":0.44}}
```

- `move_i`：只让这几个字动，其余留在原地——"走远"两个字退着缩小淡出，其余不动
- `t0`：轨迹的**统一起跑秒数**。多字一起飘时必须给，否则跟着各自出场时间起步，走不成一队
- `d0/d1`：起点/终点偏移；`frz0/frz1` 旋转；`scale` 缩放；`dur` 时长
- `hold_end`：**只延长显示时长，不改逐字节奏**。要留时间给飘散，改的是这个，不是 `end`
- `d1_i`：单个字额外的终点偏移，`{"13":[78,22]}`——一起飘的几个字要给不同终点，
  否则会平行移动、挤成一坨

**载体**（`carrier`）——让字本身变成物件：

```json
{"start":189.0,"end":192.0,"text":"我唱告白气球","x":960,"y":936,"fs":66,
 "carrier":"balloon","carrier_fills":[[232,156,138],[242,228,203],[191,211,232]],
 "move":{"d0":[0,26],"d1":[0,-104],"sway":18,"frz0":-5,"frz1":6,"fade":[300,260]}}
```

- 载体用 `\p1` 矢量画：椭圆球体 + 三角气嘴 + 两段折线细绳，字号只占球心
- `carrier_fills` 逐字配色；字色按球面亮度自动翻转（亮球用墨字、暗球用米字）
- 载体模式**必须换无底样式**（`BorderStyle=1`、无描边无阴影），否则纸卡比球还宽，整个盖住

三个坑：

1. `\an7` 对 `\p1` 图形是按**外框**定位，不是按坐标原点——小图形（高光）会被外框带偏
2. `\pos` 和 `\move` 不能同时出现；形状要用 `\an7` 并把坐标换算到左上角
3. 载体占用宽度要放宽到 1.7 倍字号，否则气球会互相咬在一起
4. **`emph` 和 `move` 别同时用在一句上**：放大过的字纸片更宽，会盖住相邻字，
   飘起来就是两片叠在一起。要重音就重音，要飘就飘

### 片头：歌曲信息要"长在画面里"，不能是字幕层

**这一条是硬规矩，不是风格选择。** 片头的歌名、歌手、作词作曲，
必须是**画面的一部分**——和横幅一起被风吹、跟镜头一起推近。
一旦它是一层叠在画面上的字幕，就会出下面这些一眼假的问题：

| 后期叠字幕 | 生成进画面 |
|---|---|
| 纸页在摆，字钉死不动 | 字随纸一起摆 |
| 镜头推近，字幕纹丝不动 | 字跟着画面一起放大 |
| 纸有透视，字是正面平的 | 字贴合纸的角度 |
| 观众看到的是"字幕条" | 观众看到的是"一块写了字的纸" |

所以片头信息**不能走字幕轨**（lines.json / ASS 那套）。它要走画面。

再往上一层：**载体要有出处**。作业本、车票、信纸、票根、便签——
选一个和这首歌的世界有关的，"写在纸上"才有理由。一块干净白板谁都能用，
作业本只能属于《等你下课》。换歌就换载体，别所有歌都用同一块纸。

#### 三条硬指标（写完必须量，不能凭感觉）

片头标题不是"排上去就行"，它要满足三个可量化的条件。少一条，手机上就废了。

**① 居中：文字块中心 = 画布中心**

误差控制在 20px 以内。做到这一点有两个动作，缺一不可：

- 文字块在**载体内**垂直居中（不是靠上、不是靠下）
- 推镜的 `x/y` 锚点 = **载体中心**，让载体中心正好落在 (960, 540)

换算公式（推镜倍率 z，载体中心 `cx/cy` 为原图坐标）：

```
out_x = 960 + (x - cx) * z
out_y = 540 + (y - cy) * z
```

**② 显眼：标题宽度占画面 40–55%**

低于 40% 就成了"画面里的一行小字"，观众不会把它当标题。
不够就两条路一起加：字号加一档、推镜再近一点。

**③ 手机上能读**

1080p 的 40% 是 768px。手机竖屏播放时画面被缩到约 375px 宽，
标题只剩 ~150px —— 四个字每个 37px，刚够认。
所以**导出后必须缩到 375px 宽自检一次**：

```bash
ffmpeg -i 成片.mp4 -ss 3 -frames:v 1 -vf scale=375:-1 check.png
```

看不清就回去加字号，别指望观众放大。

#### 怎么量

```python
# 抽一帧，量文字块中心与宽度
im = np.asarray(Image.open("frame.png").convert("RGB"))
g = im.mean(2)
sub = g[by0:by1, bx0:bx1]          # 只取载体内部，别把墙上的阴影算进去
ys, xs = np.where(sub < 100)       # 深色字
print("中心", (xs.min()+xs.max())/2 + bx0, (ys.min()+ys.max())/2 + by0)
print("占画面宽 %.0f%%" % ((xs.max()-xs.min()) / im.shape[1] * 100))
```

⚠️ 取区域时**一定要限定在载体内部**。我第一次直接把整帧拿去阈值，
把屋檐阴影和门洞都算成了"字"，量出来 75%，完全失真。

#### 两种"进画面"的做法

| 做法 | 可靠性 | 适用 |
|---|---|---|
| **A. 模型直接画出来** | 低。汉字错字率极高 | 只有纯大字标题、无小字署名时可以考虑 |
| **B. 合成进帧内再推镜** | 高。文字来自字库，零错 | 默认走这条 |

关键区别不是"谁画的"，而是**字最终是不是画面的一部分**。B 做法里，
字被合成进那一帧之后，整张图就是"画面"，推镜时字和纸是同一张图里的东西，
永远不会漂——它在效果上完全等同于"生成进画面"。

#### A 做法（模型直出）的实测边界

五次生成，没有一次汉字全对：

| 第几版 | 结果 | 错在哪 |
|---|---|---|
| 1 | 标题对，署名全糊 | 三行小字变成乱码 |
| 2 | 标题对，署名臆造 | 冒出"梁奕奕""何奕奕"这类不存在的字 |
| 3 | 标题和歌手都对 | 但用**繁体**：課、楊 |
| 4 | 加了简体约束 | "伦"写成"论"，形近字串了 |
| 5 | 改成大白话 | 小字仍然崩 |

规律：

- **字越大越准，越小越糊**。90px 标题基本对，30px 署名胜率极低
- **繁简混用**是高频故障，训练语料偏书法、偏繁体，模型默认走繁体
- **形近字会串**：伦/论、课/棵、末/未
- **提示词管不住**。写"简体中文""不要繁体"，它只当风格倾向，不当执行规则

原因是模型没有字形表——它在"画像素"，每一笔都是猜的。

> 结论：**A 只适合纯大字标题。有署名就老老实实走 B。**

#### B 做法：三段式

**① 生成一版完全没有字的场景**

```
Cinematic plate shot with NO TEXT AT ALL. Handcrafted paper-craft stop-motion
diorama of a narrow miniature alley at golden hour ... A completely BLANK cream
paper banner with torn edges is strung across the alley between two buildings,
swaying very gently. The banner surface is empty, clean, with only subtle paper
fibre texture ... Absolutely no text, no letters, no characters, no writing
anywhere in the frame.

negative: text, letters, characters, writing, words, typography, logo, watermark,
Chinese characters, signs, labels, garbled marks, traditional Chinese
```

标题里写 `NO TEXT AT ALL`，句末再重复一遍 `absolutely no text`，
negative 挂 `text / letters / Chinese characters`。**少一处它就会自己添字。**

**② 取一帧，把字排到载体上（字库，零错）**

**③ 让这一帧动起来（两种，按需要选）**

**③-a 只有推镜（静态感强，但最稳）**

```bash
ffmpeg -i still.png -vf "scale=3840:2160,\
 zoompan=z='min(1.74+0.00035*on,1.84)':d=144:\
 x='max(0,1836-(iw/zoom)/2)':y='max(0,716-(ih/zoom)/2)':\
 s=1920x1080:fps=24" -t 6 -c:v libx264 -crf 17 title.mp4
```

**③-b 图生视频（纸页会摆、鸽子会飞，但要多一道裁切）**

把 `still.png` 喂给 VideoGen 做 image-to-video，`last_image` 传同一张，
prompt 反复强调 "the banner and every character printed on it must stay perfectly
sharp, flat, stable and completely unchanged"，negative 挂 `warped text`,
`changed characters`, `rippling paper`。

**文字烧在首帧里，所以模型只做运动，字不会错**——这一路是可靠的。

但有个必然的副作用：**模型会重新"看"一遍场景，把镜头拉远**。
你喂进去的是 40% 的标题，出来只剩 25%。锁机位提示（locked-off camera,
no zoom, no pull-back）拦不住，试两次都一样。

所以 ③-b 之后必须补一道裁切，把占比拉回来：

```bash
# 裁掉 0.625 的面积再放大，标题从 25% 回到 40%
ffmpeg -y -i gen.mp4 \
  -vf "crop=1200:675:380:42,scale=1920:1080:flags=lanczos,\
unsharp=5:5:0.45:5:5:0,format=yuv420p" -c:v libx264 -crf 17 title.mp4
```

裁完会软一点，但纸雕这种质感吃得住，加一道 `unsharp` 就够。

**接缝用叠化，别硬切**：

```bash
[0:v]trim=0:6,setpts=PTS-STARTPTS,fps=24[t];
[1:v]trim=5.7:270,setpts=PTS-STARTPTS,fps=24[b];
[t][b]xfade=transition=fade:duration=0.3:offset=5.7
```

⚠️ `trim` 之后帧率信息会丢，`xfade` 会报 `current rate of 1/0 is invalid`。
**两个分支都要在 `setpts` 后面补 `fps=24`**，否则滤镜图根本建不起来。

**④ 拼到片头：只换画面，不动音轨**

```bash
ffmpeg -i title.mp4 -i base.mp4 -filter_complex \
"[0:v]trim=0:6,setpts=PTS-STARTPTS[vt];\
 [1:v]trim=6:270,setpts=PTS-STARTPTS[vb];[vt][vb]concat=n=2:v=1:a=0[v]" -map "[v]" base4.mp4
```

**⑤ 从 lines.json 里删掉标题项**，并在 build_lines 里留开关：

```python
TITLE_BAKED = True     # 标题已在画面里，不再叠字幕
if not TITLE_BAKED:
    items.insert(0, dict(...))
```

#### 字体细节（照这组数走）

| 项 | 标题 | 署名 |
|---|---|---|
| 字体 | MV Serif SC（思源宋体子集化） | 同族 |
| 字号 @1080p | **112** | **38**（= 标题的 1/3） |
| 字距 `\fsp` | **8** | **6** |
| 倾斜 `\frz` | **−1.5°**（跟横幅角度） | 同角度 |
| 字色 | `#261E1A` 暖墨 | `#342C24`，略浅 |

- **必须用衬线**。宋体的横细竖粗是这个纸雕世界的"印刷味"，无衬线会像 UI
- **字色不要纯黑**。纯黑压在米色纸上像贴纸，暖墨（带一点红）才像印上去的
- **字距是标题感的主要来源**。正文 0–2，标题 10–38；挤在一起字号再大也是字幕
- **倾斜必须和载体一致**。横幅歪 1.5°，字就得歪 1.5°，否则一眼看出是贴上去的
- **字号关系定死**：署名 = 标题 × 1/3。差太多会变成两行同级标题
- **先定"在成片里占多大"，再倒推字号**。检验标准是成片不是设计稿：
  标题最终要占画面宽度的 **40–55%**，否则手机竖屏一缩就成了小字条。
  我第一次按横幅比例给到 92 号，在 1080p 上看没问题，一上手机就太小——
  后来加到 112 号 + 镜头推近（1.74×）才够

排字用的 ASS：

```
Dialogue: 0,0:00:00.00,0:00:10.00,T,,0,0,0,,{\an5\pos(920,326)\frz-1.5\fsp8}等你下课
Dialogue: 0,0:00:00.00,0:00:10.00,S,,0,0,0,,{\an5\pos(920,438)\frz-1.5\fsp6}周杰伦 / 杨瑞代
```

#### 踩坑点

1. **别走字幕轨**。片头挂进 lines.json 是最省事、也最容易露馅的路——
   字不跟画面动，纸在摆它不动
2. **别让模型写小字**。30px 以下的汉字，五个版本里没有一个是对的
3. **繁简混用要专门查**。模型会自己把"课"写成"課"、"杨"写成"楊"，
   生成完必须逐字放大核对，不能只看整体像不像
4. **拼接只能换画面，不能改总长**。把标题插到最前面、整片往后推，
   音轨就全错位了；正确做法是用标题覆盖掉原片前 N 秒的**画面**，音轨不动
5. **zoompan 前必须 `scale` 放大预处理**，否则推镜会糊成一片
6. **zoompan 的 x/y 要锁载体中心**，不是锁画面中心，否则推着推着title就偏出画
7. **生成片常带"AI生成"角标**。位置若与原片水印重合，同一条 `delogo` 会一起抹掉；
   要保留就把它排除在 delogo 区域外
8. **署名行不要超过两行**。两行以内还能看，三行开始必然挤成一团乱码

### 三个可直接套用的取色

以本站这部纸雕 MV 为例（`ink` / `edge` 都是 0–255 的 RGB）：

| 场景 | 背景主色 | ink（字） | edge（描边） | fs |
|---|---|---|---|---|
| 深蓝星空 | `#062344` | `#E4D5C4` 星光米金 | `#0A2B52` 海军蓝 | 104 |
| 黄昏校园 | `#A8968B` | `#4A3A36` 暗赭 | `#E8DCCE` 米白 | 100 |
| 人海俯拍 | `#BA9F89` | `#563E2C` 深褐 | `#F0E4D2` 米白 | 92 |

三处都撤了卡、都放大到 92–104 号（常规纸卡是 66），入场只淡入不弹跳。
多了会腻，少了不够——**观众记住的往往就是这几个瞬间**。

## 十、小尺寸可读性：16:9 发竖屏信息流的补偿规则（2026-10-26）

**画幅固定 16:9，不改。** 但要承认一个事实：16:9 的片在竖屏信息流里，
上下是大片黑边，**有效注意力集中在画面中央那一条**。
所以字和钩子元素的摆法要按"中央一条"来设计，不能按满屏设计。

### 10.1 三条摆位规则

1. **钩子元素、开场概念字放画面中央偏上**，不要贴左右边、不要压底边。
   底边在信息流里会被文案、按钮、进度条压住；左右边在缩略状态下最先被忽略。
2. **开场概念字要明显大于歌词字幕。** 它是"让人停下来"的字，不是"跟着唱"的字。
   歌词字幕可以优雅收敛，开场字必须一眼可读。
3. **概念字与歌词字幕要在视觉上区分开**（位置或字号至少差一档），
   否则观众会把概念字当成歌词，等它"唱过去"。

### 10.2 把 375px 自检从"看一眼"变成有数值的硬检查

375px 宽自检时，1080p 里的字号会按 `375/1920 = 0.195` 缩小。
**要单字 ≥14px，反推 1080p 字号必须 ≥72。**

| 用途 | 375px 下要求 | 1080p 下对应字号 |
|---|---|---|
| 歌词字幕 | 单字 ≥14px | **fs ≥ 72** |
| 开场概念字 / 钩子字 | 单字 ≥20px | **fs ≥ 102** |

低于这个数，不是"有点小"，是**在手机上读不出来**。

### 10.3 自检必须覆盖开头，不许只抽中间

最常见的漏检：抽的全是正片中间的帧，开头三秒一次没看。
而开头恰恰是唯一决定 2 秒跳出的地方。

```bash
# 开头三帧 + 一句正片字幕，全部缩到 375px 看
for t in 0 1 3 30; do
  ffmpeg -y -ss $t -i out/final.mp4 -frames:v 1 -vf scale=375:-1 work/qa_375_$t.png
done
```

逐张问三个问题：
- **首帧**：有没有内容？（全黑 = 直接返工，见 `06-title-card.md` 第〇节）
- **第 1 秒**：画面里有没有"在动的东西"？有没有可读的字？
- **第 3 秒**：观众能不能说出"这是一条什么视频"？

三个问题有一个答不上来，就回 `04a-timeline.md` 第 6 节重排前奏。
